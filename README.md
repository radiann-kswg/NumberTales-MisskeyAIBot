# NumberTales Misskey AI Bot

**ナンバーテールズ0番機 000(チトセ)** を模した生成 AI Bot を [Misskey](https://misskey-hub.net/)（分散型SNS）上で動作させるリポジトリです。

> キャラクター「ナンバーテールズ」は百花繚乱研究所（著作権者: RadianN_kswg）制作の創作シリーズです。
> 本 Bot および関連コードは [CC BY-NC 4.0](https://creativecommons.org/licenses/by-nc/4.0/) に従って公開されています。

## 実装済み機能

### F-01: メンション応答

ユーザーからのメンションに対して 000(チトセ) として返答します。

- **意図分類**（ルールベース正規表現）により 4 種類の挙動を切り替え
  - `greeting` — 挨拶への定型返答
  - `form-switch` — コアフォルダ / ヒューマノイド形態切り替え演出
  - `creative-consultation` — 創作壁打ちモード（専用プロンプトで LLM 生成）
  - `chat` — 通常雑談（セッション履歴付き LLM 生成）
- 返答書式: `000 :aphrnts0_corefolder:「台詞」`（カスタム絵文字付き）
- 100 文字超の返答は CW（ContentWarning）`000の返信` で折りたたみ
- 返信後に元ノートへカスタム絵文字リアクションを自動付与

### F-02: 時間帯別自発投稿 / 週次担当キャラクター選出

1 日 4 スロットで担当キャラクターがホーム公開でつぶやきます。
担当キャラクターは毎週日曜に Misskey の Poll（投票ノート）で決定され、月曜から翌週担当として就任します。

| スロット | 時間帯 (JST) | テーマ             |
| -------- | ------------ | ------------------ |
| 朝       | 6:00〜8:00   | 軽い挨拶・作業開始 |
| 昼       | 12:00〜13:00 | 落ち着いたつぶやき |
| 夕方     | 17:00〜19:00 | 終業・作業まとめ   |
| 深夜     | 23:00〜5:00  | ほっこり・哲学的   |

各スロットのクールダウンはランダム 1〜2 時間。10 分ごとに発火判定。

**週次担当選出フロー**

1. 土曜 0:00 — `Progress: released` キャラから**重み付きランダム**で 3 名を候補とした Poll ノートを投稿（投票期間: 48 時間）
2. 日曜 23:59 — 票数を集計し最多票キャラクターを翌週担当として確定
3. 月曜 7:00 — 就任挨拶（LLM 生成・50 文字以内）を投稿
4. 同票 / 票ゼロ時は同数票の中からランダムで自動決定

**候補選出の優先度（Tier）**

| Tier | 条件 | 相対重み |
| ---- | ---- | -------- |
| 1 | `ConversationPattern`（会話パターン）が創作 DB に収録されている | 15 |
| 2 | `Character` / `Summary` / `Relation.Commented` により口調補完が可能 | 3 |
| 3 | 上記以外（基本情報のみ） | 1 |

- 固定除外: 000(チトセ)・1(ハジメ)・10(ミツル)・0(零/かずない)・00(零百/かずない-はげむ)、特殊番号（`2-alt` など）
- コアフォルダ絵文字（`:aphrnts{Num}_corefolder:`）が Misskey サーバーに未登録の場合は候補から除外
  - 未登録時はカテゴリ・タグ情報をもとに代替絵文字を自動解決
- 前週の候補と同じキャラクターは今週は除外（連続選出防止）

**投票ノートのリマインド**

土曜 7〜23 時・日曜 7〜23 時の毎時 0 分前後に投票ノートをセルフリノートしてリマインドする。

### F-03: 創作壁打ちモード / グローバルTL検出

「お題ください」「世界観について教えて」などのメンションに対し、
**創作支援専用システムプロンプト**で LLM が応答します（200 文字以内・CW 付き）。

グローバルタイムライン上でナンバーテールズ関連ハッシュタグ（`#ナンバーテールズ` など）を含む投稿を検出し、
文脈に応じたリアクション絵文字を自動送信する機能も含みます。

### F-04: リアクション・エモパシー

フォロイーのホームタイムラインを購読し、感情文脈を読み取ってカスタム絵文字リアクションを送ります。

- **対象**: フォロイーのノート（homeTimeline チャンネル）
- **フィルタリング**: 画像添付・高度 MFM・絵文字 3 個以上・50 文字超はスキップ
- **感情カテゴリ** → 絵文字の例:
  - 完成・達成 → `yattaze_aphrnts41`（やったぜ！）
  - 疲労・お疲れ → `otukaresama_aphrnts31`（お疲れ様）
  - 共感・いいね → `iine_aphrnts42`（いいね）
  - 面白い・発見 → `omoshiroi_i_aphrnts65`（面白い！）
  - かわいい・素敵 → `kawaii_aphrnts6`（かわいい）
  - 挨拶系 → 朝/帰宅/出発/夜に応じた絵文字
  - 応援 → `ganbare_aphrnts93`（がんばれ）
- **レートリミット**: 同一ユーザー 1 時間 1 回・全体 20 回/時

### F-06: 数字・ヌメロジーコマンド / ミニゲーム

メンションに数字絡みのキーワードが含まれる場合、数値計算・ヌメロジー占い・ダイスロール・各種ミニゲームに対応します。

**数字・占い系**

- **計算** — 自然文中の数式（`3+5` など）または `/calc 式` コマンドを評価し結果を返答
- **ライフパスナンバー** — 生年月日から数秘術のライフパスナンバーを算出し CW 付きで解説
- **九星気学** — 生年月日から本命星・月命星を算出し CW 付きで解説
- **ダイスロール** — `/dice NdM` 形式または「N面ダイスを振って」等の自然文でダイスを振る
- **数字うんちく（LLM）** — `/trivia N` で指定した数字にまつわる雑学を LLM 生成
- **ヌメロジー相談モード** — ライフパス・九星のより詳しい相談に LLM が応答

**ミニゲーム**（Secvier シリーズカスタム絵文字で演出）

| コマンド例 | ゲーム | 内容 |
| ---------- | ------ | ---- |
| 「スロット回して」`/slot` | **数字スロット** | 0〜9 の 3 桁抽選・ゾロ目/リーチ/昇降順の役判定 |
| 「ポーカーやって」 | **ポーカー** | 52 枚デッキから 5 枚ドロー・10 段階役判定（トランプ絵文字表示）。配札後に1回だけカード交換可能（「交換 1 3」/「このまま」） |
| 「麻雀配牌チャレンジ」 | **麻雀配牌チャレンジ** | 14 枚配牌・役判定（麻雀牌絵文字表示）。最大10回までツモ交換可能（「打牌 3」、「あがり」で確定） |
| 「ヨットやって」 | **ヨット** | 5d6 を最大 3 回振り直し・役判定（丸数字位置表示・出目ベース振り直し指定・ダイス絵文字キープ色変え演出。振り直し指定は丸数字・全角数字での返信にも対応） |
| 「ヒット＆ブロウやって」「6桁で重複ありのヒットアンドブロウ」「アルファベットでワードウルフ」 | **ヒット＆ブロウ** | Bot が 2〜8 桁（デフォルト4桁）の数字、またはアルファベット26種（ワードウルフ風・実在英単語）を設定して当てる数当てゲーム（「重複あり」指定で桁の重複も許容、アルファベットモードは単語当てのため常に重複あり固定）。回答ログは色分けしたシンボルタイルで CW 記録: 赤=ヒット/青=ブロウ/白=非該当、重複ヒット時は黄/緑の別色で識別。「結果発表のみ色ヒント」指定でゲーム進行中は色を白固定にし、終了時にのみ色ヒントを表示するモードにも対応。進行中に桁数・重複あり等の条件変更を含むリプライが来た場合は、条件変更の指示とみなし自動で再スタートする |
| 「ルーレット回して」「キャラを引いて」 | **キャラ番号ルーレット** | 公開済みキャラクターから1体を一様ランダムに抽選し、番号を抽選キャラ自身の桁根カラーの数字絵文字で表示（CW内で結果を公開する「めくり」演出） |
| `/dice NdM`（自然文でも可） | **汎用ダイスロール** | 担当キャラクター番号の桁根から色を決め、対応面数（d4/d6/d8/d10/d12/d20/d100）は出目絵文字で表示 |

- 同一ユーザーが複数ゲームを並行して起動することはできません（セッション 60 分 TTL）
- ターン制ゲーム中はメンション文字列をゲームコマンドとして解釈します
- **「もう一回」等の継続コマンド** — 直近 10 分以内にプレイした6ゲーム（スロット/ポーカー/ヨット/ヒット＆ブロウ/麻雀配牌チャレンジ/キャラ番号ルーレット）のいずれかを自動再開（10 分間に 3 回まで）。アクティブなセッションがある場合はそちらの終了を促します
- **ヨットの振り直し確認** — 出目ベース指定（「3の目を振り直し」等）や一括指定（「全部」）など解釈を伴う指定は、実行前に一度確認を挟みます
- 桁数・振り直し位置などの数字指定は、半角数字だけでなく丸数字（①②③…）・全角数字（１２３…）での返信も解釈します

### マルチキャラクター切り替え

000(チトセ) 以外の公開済みナンバーテールズ各個体を名前指定で呼び出せます。

- **切り替えトリガー** —「◯◯と話したい」「◯◯を呼んで」などのキーワード + キャラクター名
- **対応キャラクター** — 創作 DB（`_creations-db`）の `Progress: released` キャラクター全員
- **システムプロンプト動的生成** — 呼び出し対象のキャラクター DB データを元にプロンプトを自動構築
- **切り替えメッセージ LLM 生成** — 「◯◯に繋ぎます」系の台詞を DB 情報を元に LLM が自然文生成
- **デフォルト担当へのリセット** — 「通常担当に戻して」等で 000(チトセ) に戻る
- **ヘルプコマンド** — 「誰と話せる？」で呼び出せるキャラクター一覧を返答

### フォローバック

`followed` イベント（フォローされた通知）を受信した際、自動でフォロー返しを行います。

- 同一ユーザーへの重複フォローバックを 5 分間のクールダウンで防止

### F-07: ハラスメント仲介

不適切・ハラスメント的なメンションに対し、担当キャラクターがパーソナリティを保ちながら対応します。
重大度に応じて 000(チトセ) または 10(ミツル) が仲介に入る 3 段階の仕組みです。

| レベル | 判定基準                                          | 対応                                          |
| ------ | ------------------------------------------------- | --------------------------------------------- |
| L1     | 軽度の不躾な要求・軽い挑発                        | 担当キャラがパーソナリティを保ちながら受け流す |
| L2     | 不適切な性的要求・個人情報要求・エスカレートした言動 | 000(チトセ) が「設計上の制約」として介入      |
| L3     | 明らかな暴言・威圧・脅迫レベルの言動              | 10(ミツル) が毅然と制止し担当キャラを守る     |

検知はルールベース正規表現（L3→L2→L1 の優先順で判定）。
ハラスメント検知時は投稿者情報（ユーザーID・ハンドル・投稿日時・テキスト）をインシデントログファイルに記録します。

### F-12 / F-12B: タスク＆スケジュール管理 + 信頼度システム

「〇時間後に〇〇を教えて」「明日の会議を登録して」のように伝えると、担当キャラクターがタスクとして
記録し、期日・優先度・難易度を踏まえて管理・通知します。主従契約の世界観のもと、タスク完了や日々の
会話を通じてユーザーごとの「信頼度」が蓄積し、関係の深さに応じてキャラクターの口調が自然に変化します。

| コマンド例 | 内容 |
| ---------- | ---- |
| 「3時間後に薬を飲むのを教えて」「明日の10時に会議があるから登録して」 | タスク登録（内容・期日・通知日時・優先度・難易度は LLM が自然文から抽出） |
| 「タスク一覧見せて」「進捗はどのくらい？」 | 登録済みタスクと重み付き進捗％を表示（一覧の番号は丸数字・全角数字での返信にも対応） |
| 「設計書終わった」「3番のタスク完了」「①終わりました」 | タスクを完了にする（内容一致 or 番号指定・丸数字/全角数字可。複数候補時は番号で再指定を促す） |
| 「設計書のタスクをキャンセルして」「3番のタスクを消して」 | タスクをキャンセルする |
| 「1番の進捗を70%にして」 | タスクごとの進捗％を手動更新する（全体の重み付き進捗％はタスクごとの値の加重平均で再計算） |

- タスク種別は自然文から `todo`（期日なし）/ `alert`（通知希望）/ `schedule`（予定）を自動判定
- 同時アクティブ上限は1ユーザー10件、通知日時は指定可能なら1分後〜365日以内
- 配信は5分間隔のスケジューラーがチェックし（1回あたり最大5件の安全上限つき）、`visibility: home` で
  本人宛てメンション付きノートとして送信。期日超過も別途1回だけ通知、期日・通知日時の有無に関わらず
  未完了タスクへ12時間ごとの定期催促も送信
- 通知の発言キャラクターは週次自発投稿担当ではなく、**そのタスクを持つユーザーが現在会話しているキャラクター**
  （マルチキャラクター切り替えで指定した相手）を使用
- 進捗％は優先度×難易度の重み付き計算（易しい低優先タスクを大量にこなしても伸びにくい設計）。タスクごとの
  進捗値はプロンプトで手動更新可能（完了時は自動的に100%扱い）
- 信頼度はタスク完了・schedule通知・1日1回の会話ボーナスでポイントが貯まり、5段階（初対面〜主従の契り）で
  キャラクターの応答トーンに反映（数値や信頼度そのものには言及しない）

### ログファイル管理

Bot は PM2 コンソールログに加え、2 種類のファイルログを `.cache/` 配下に出力します。

| ファイル               | 内容                                                |
| ---------------------- | --------------------------------------------------- |
| `.cache/incident.log`  | ハラスメント検知時の投稿情報（NDJSON 形式）         |
| `.cache/error.log`     | `error` / `warn` レベルのシステムログ（NDJSON 形式）|

```bash
# インシデントログ確認
tail -n 20 .cache/incident.log
grep '"level":3' .cache/incident.log   # L3 のみ抽出

# エラーログ確認
tail -n 20 .cache/error.log
```

### 自動復旧（3層ウォッチドッグ）

エラー落ち・ハング・VM 障害から人手を介さず復旧します（詳細: [docs/deployment.md](./docs/deployment.md) §5）。

| レイヤー | 障害 | 復旧手段 |
| -------- | ---- | -------- |
| 1 | プロセスのクラッシュ | PM2 `autorestart` |
| 2 | ハング・WS切断継続・`errored` 放置 | ハートビート（`.cache/heartbeat.json`・30秒毎）＋ VM内ウォッチドッグ（`tools/vm-watchdog.mjs`・systemd timer 毎分） |
| 3 | VM ごとフリーズ・停止 | GCE 外部ウォッチドッグ（Cloud Scheduler + Cloud Run functions → reset/start、[tools/gce-watchdog/](./tools/gce-watchdog/README.md)） |

## セットアップ（簡易）

```bash
# 1. リポジトリをクローン
git clone https://github.com/radiann-kswg/NumberTales-MisskeyAIBot.git
cd NumberTales-MisskeyAIBot
git submodule update --init --recursive

# 2. 依存パッケージのインストール
npm install

# 3. 環境変数の設定
cp .env.example .env
# .env を編集して API トークンを設定

# 4. ビルド & 起動
npm run build
npm start
```

詳細は [docs/development.md](docs/development.md) / [docs/deployment.md](docs/deployment.md) を参照してください。

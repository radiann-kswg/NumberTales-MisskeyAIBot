### D1. F-04 改善: リアクション感情分類のLLM駆動化

**現状の問題:**

- classify.ts の正規表現マッチは「単語の有無」で判定するため、文脈・ニュアンスを読めない
- 「打ちのめされてる」のような否定的文脈に `知見` が含まれると誤って `interesting` に分類される
- 「悩み・落ち込み」など現状のカテゴリにない感情パターンへの対応がない

**改修方針:**

```
現状: cleanText() → 正規表現マッチ → ReactionCategory
改修: cleanText() → LLM分類プロンプト → ReactionCategory | 'skip'
```

LLM への入力は `cleanText` 済みの短文（50文字以内フィルター後なので安い）、出力はカテゴリ名の1単語のみに制約する。コストと精度のバランスを取るため、**挨拶系はそのまま正規表現で先行判定**し、それ以外の感情カテゴリのみ LLM に渡す混在方式が現実的。

| 比較                               | 現状（regex）         | 改修後（LLM）                     |
| ---------------------------------- | --------------------- | --------------------------------- |
| 「知見がなくて打ちのめされてる」   | `interesting` ❌      | `skip`（否定文脈を認識） ✅       |
| 「ようやく完成した！知見が増えた」 | `interesting` ✅      | `achievement` or `interesting` ✅ |
| 「おはよ～」                       | `greeting_morning` ✅ | 正規表現で先行処理 ✅             |

**追加カテゴリの検討:**

- `sympathy`（落ち込み・悩みへの共感）→ `:murisinaide_aphrnts20:` / `:yoshi:`

### D2. グローバルTL からのナンバーテールズ関連タグ検出（F-05 拡張）

**提案仕様:**

- **観測対象:** グローバルTL（`globalTimeline` チャンネル）
  - ホームTLより広いリーチ。フォロー外のナンバーテールズ言及を検出できる
- **検出条件:**
  - `#ナンバーテールズ` / `#NumberTales` などの関連タグを含む投稿
  - 関連ハッシュタグ一覧は設定ファイルで管理
- **除外条件（重要）:**
  - Bot アカウント自身の投稿（`userId === botUserId`）
  - 自動投稿ぽい投稿（`renoteId` あり かつ `text` 短い、等）

  - `interesting` / `cute` 系のリアクション絵文字を送る（F-04 の流用）

### D3. 数字ミニゲーム機能（F-06 拡張・新フィーチャー）

**コンセプト:** F-06 の延長として「数字で遊ぶ」体験を追加。ナンバーテールズの個性を LLM で演出させる点は既存 F-06 と同様。

#### D3-1. 数字スロット

- コマンド例: 「スロット回して」「スロット」
- 動作: 1〜9 の数字を 3 桁（例: 3-7-1）ランダム生成し、絵柄（後で登録するカスタム絵文字）で演出
- 役判定: ゾロ目・リーチ・バラバラ等
- LLM 演出: 結果の数字の組み合わせに 000(チトセ) らしいコメントを添える

#### D3-2. カード/ダイスゲーム（ポーカー・ヨット系）

- コマンド例: 「カードゲームしよう」「ヨットやって」
- ポーカー: 5枚のカードを引いて役を判定（ワンペア〜フルフラッシュ）
- ヨット: 5d6 を振って役を判定（ヤッツィー系）
- セッション管理: SQLite の会話履歴を流用してゲーム状態（手札・ターン数）を保持
- LLM 演出: アクティブキャラクターの口調でゲームの実況コメントを生成

#### D3-3. ヒット＆ブロウ（数当てゲーム）

- コマンド例: 「数当てゲームしよう」「ヒットアンドブロウ」
- 動作: Bot が 3〜4 桁の数字を設定 → ユーザーが数字を予想 → ヒット/ブロウ数を返す
- セッション管理: ゲーム状態（正解・試行回数）を SQLite で保持
- LLM 演出: キャラクターが煽ったり励ましたりしながら正解発表

**実装上の共通事項:**

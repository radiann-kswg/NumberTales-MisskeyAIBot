## 機能①: ヌメロジー相談モード（F-06 拡張）

### コンセプト

「岡部るびぃ」のタロットリーディングのように、
ユーザーの**悩み・文脈とヌメロジーの結果を絡めて** LLM が自然な解釈文を生成する。

ナンバーテールズが「数字・ヌメロジーをモチーフにした癒し的存在」であることを
ユーザーが実感できる体験として設計する。

### 現状の F-06 との違い

| 現状 F-06（コマンド型）            | 機能①（相談型）                                    |
| ---------------------------------- | -------------------------------------------------- |
| コマンド入力 → 数値計算 → 定型解説 | 悩み文脈 + ヌメロジー結果 → LLM が自然な解釈文生成 |
| 担当キャラクターによる差異なし     | 担当キャラの専門性・個性が解釈の切り口に反映される |

### 担当キャラクターによる専門性の違い（例）

| 担当キャラクター | 解釈の切り口                                     |
| ---------------- | ------------------------------------------------ |
| 78(ナナハ)       | タロットとヌメロジーを組み合わせた解釈           |
| 47(シナ)         | 数字よりも相手の「本質」を直接読み取るような解釈 |
| 74(ナナヨ)       | 天の視点・運命的な言い回しで語りかける           |
| 000(チトセ)      | エンジニア的・分析的に、でも最後は温かく締める   |

### 動作イメージ

```
ユーザー: 「最近仕事がうまくいかなくて… 1997年6月14日生まれです」
→ ライフパスナンバーを算出（既存 F-06 ロジックを流用）
→ 悩みコンテキスト + 数字の意味 + 担当キャラの専門性 → LLM で解釈文生成
→ 「ライフパスは7番だね。探求者の数字で… [CW 折りたたみで詳細]」
```

### 意図分類への追加

`classifyIntent()` に `numerology-consultation` の分岐を追加する。
トリガー例: 「生年月日」「数字で占って」「ライフパス教えて」「悩みを聞いてほしい」
「〜が気になる」「数字的に見てくれない？」 など

### タスク詳細（実装着手時に詳細化）

#### D-1: `numerology-consultation` インテントの追加

- `classifyIntent()` に新分岐を追加
- ヌメロジー相談 ← 悩みコンテキスト + 日付・数字を含む文脈 の複合判定
- 既存の `numerology`（F-06 コマンド型）と区別する

#### D-2: 相談型プロンプトの設計

- 担当キャラクターの専門性・口調を組み込んだ「相談向けシステムプロンプト」を作成
- 悩みコンテキスト、算出したヌメロジー結果をユーザーメッセージとして渡す
- 出力: 本文 100 文字以内 + CW 内の詳細解釈

#### D-3: `mention.ts` への分岐追加

- `numerology-consultation` インテント時のハンドラを追加
- 既存 F-06 の計算ロジックを流用してヌメロジー値を算出
- 算出結果 + 悩みテキストを D-2 のプロンプトに注入して LLM 生成

#### D-4: 動作確認

- 担当キャラクターが異なる場合に解釈の切り口が変わることを確認
- CW 折りたたみが正しく機能していることを確認

## 機能②: 自発投稿キャラローテーション（F-02 拡張）

### コンセプト

F-02 の時間帯別自発投稿を、前提 B（週次担当選出）で選ばれたキャラクターが行うようにする。
各個体の専門性・性格を活かした内容のつぶやきを LLM が生成する。

### 現状との変更点

| 現状 F-02                            | 機能②拡張後                                            |
| ------------------------------------ | ------------------------------------------------------ |
| 000(チトセ) 固定のシステムプロンプト | 週次担当キャラのシステムプロンプト（専門性込み）を使用 |
| 時間帯のみのプロンプト分岐           | 時間帯 × 担当キャラの専門性でプロンプト分岐            |

### 自発投稿例（担当: 74(ナナヨ) 朝スロットのイメージ）

> 「今朝の空気、なんとなく澄んでいると思う。良い日になりそうな予感がするよ」

### タスク詳細（実装着手時に詳細化）

#### E-1: スケジューラーへの担当キャラクター連携

- `scheduler/index.ts` の自発投稿処理で `bot_state` から現在の担当キャラクターを取得
  （前提 B-1 の `getState('current_scheduler_char')` を使用）
- 取得したキャラクター番号のシステムプロンプト（A-2 の専門性セクション込み）を組み立て
- 担当キャラクター未設定時は 000(チトセ) の固定プロンプトにフォールバック

#### E-2: 時間帯 × キャラ専門性のプロンプト調整

- 時間帯別の `promptAddendum`（現状: 朝/昼/夕方/深夜）に加え、
  担当キャラクターの専門性・口調を自然に混ぜた付加指示を生成するロジックを追加

#### E-3: 担当就任時の自己紹介投稿

- 前提 B-3 の担当確定直後に、担当キャラクターの就任一言（LLM 生成）を投稿
- 「今週は私が担当するよ」等のフレーズをキャラの口調で生成（50 文字以内）

#### E-4: 動作確認

- 週次担当が変わった場合に投稿キャラクターのプロンプトが切り替わることを確認
- フォールバック（000(チトセ)）が正しく機能することを確認

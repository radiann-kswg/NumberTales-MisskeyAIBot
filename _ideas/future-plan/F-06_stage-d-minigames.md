## 概要

F-06「数字・ヌメロジーコマンド」の延長として、数字をモチーフにしたミニゲームをメンション経由で遊べる機能を追加する。
既存機能と同様に、アクティブキャラクターの個性を LLM で演出させることで、
ナンバーテールズの「数字を生きる存在」としての世界観を体験できるインタラクションを提供する。

## D3-1: 数字スロット

### コンセプト

1〜9 の数字を 3 桁ランダム生成し、絵文字（数字モチーフのカスタム絵文字）で演出する。
役判定の結果に対して、担当キャラクターが数字の組み合わせにコメントを添える。

### コマンドトリガー例

- 「スロット回して」「スロット」「スロットしよう」

### ゲームフロー

1. 1〜9 の数字を 3 桁ランダム生成
2. 役判定（ゾロ目 / リーチ / バラバラ等）
3. カスタム絵文字（数字図柄）で結果を表示 ← **絵文字登録完了後に実装**
4. LLM 演出: 担当キャラの口調で「この数字の組み合わせには〜」的なコメントを生成

### 役パターン（案）

| 役名               | 条件                      |
| ------------------ | ------------------------- |
| ナンバーテールズ！ | ゾロ目（例: 7-7-7）       |
| リーチ             | 2 桁同じ（例: 3-7-3）     |
| 昇順 / 降順        | 連番（例: 1-2-3 / 9-8-7） |
| バラバラ           | 上記以外                  |

### 実装メモ

- `intent: 'game-slot'` を `classifyIntent()` に追加
- 絵文字名パターン: 数字 0〜9 に対応するカスタム絵文字（インスタンス登録後に定数を定義）

## D3-2: カード / ダイスゲーム（ポーカー・ヨット系）

### コンセプト

ランダムなカードやダイスの目から役を作るゲーム。
ターン制のやり取りを SQLite セッションで管理し、担当キャラが実況コメントを生成する。

### コマンドトリガー例

- 「ポーカーしよう」「カードゲームしよう」
- 「ヨットやって」「ダイスゲームしよう」

### ポーカー仕様（案）

1. Bot が 5 枚のカードを引く
2. 役判定（ワンペア〜フラッシュ・ストレート・フルハウス 等）
3. 結果と役名をテキストで表示
4. LLM 演出: 担当キャラの口調で役に合ったコメントを生成

### ヨット（ヤッツィー系）仕様（案）

1. Bot が 5d6 を振る（`Math.random()` で代替可）
2. 役判定（ヤッツィー・フォーカインド・フルハウス 等）
3. 最大 3 ターン（振り直し選択）— セッション管理が必要
4. LLM 演出: ターンごとにキャラがリアクション

### 実装メモ

- ターン制ゲームのセッション管理は `storage/session.ts` の SQLite を拡張して保持
- `intent: 'game-poker'` / `'game-yacht'` を追加
- 同一ユーザーのゲームセッションは 1 つまで（並行ゲーム禁止）
- セッション TTL はゲーム完了 or 30 分で自動終了

## D3-3: ヒット＆ブロウ（数当てゲーム）

### コンセプト

Bot が 3〜4 桁の数字を設定し、ユーザーが数字を予想する数当てゲーム。
正解に近づくにつれて担当キャラが煽ったり励ましたりする。

### コマンドトリガー例

- 「数当てゲームしよう」「ヒットアンドブロウやって」「数字を当てて」

### ゲームフロー

1. Bot が 3〜4 桁（重複なし）の数字をランダム生成 → SQLite に保存
2. ユーザーが数字を投稿（例: 「1234」）
3. Hit 数（桁・位置とも一致）/ Blow 数（数字のみ一致）を返答
4. 正解 or 規定回数（例: 10 回）超過でゲーム終了
5. LLM 演出: 各ターンのヒット/ブロウ数に応じてキャラがコメント

### 実装メモ

- `intent: 'game-hitblow'` / `'game-guess'`（ゲーム中の予想投稿）を追加
- ゲーム中の予想投稿はメンションテキストから数字のみ抽出
- セッション TTL はゲーム完了 or 60 分で自動終了

## ゲーム機能共通の実装方針

### LLM 演出

- F-06 の既存フレーミング（`buildCharacterSystemPrompt()` 流用）でキャラ個性を反映
- アクティブキャラクターの `AbilityStats` に応じて演出の「深さ・詳しさ」を変化させる
  （既存 F-06 の設計に準じる）

### セッション管理

- ターン制ゲームの状態は `storage/session.ts` の SQLite を拡張して保持
- テーブル設計（案）:
  ```sql
  CREATE TABLE game_sessions (
    user_id TEXT NOT NULL,
    game_type TEXT NOT NULL,   -- 'hitblow' | 'yacht' | 'poker'
    state TEXT NOT NULL,        -- JSON シリアライズされたゲーム状態
    created_at INTEGER NOT NULL,
    updated_at INTEGER NOT NULL,
    PRIMARY KEY (user_id, game_type)
  );
  ```

### 意図分類

- `classifyIntent()` に `game-slot` / `game-poker` / `game-yacht` / `game-hitblow` を追加
- ゲーム中の「予想入力」は既存ゲームセッションの有無で判定する

## D3-2c: 麻雀配牌チャレンジ ✅（2026-06-29 実装）

### コンセプト

136 枚の標準麻雀デッキから 14 枚を配牌し、役判定結果を `sv_mj_*` 絵文字で表示するワンショットゲーム。
「配ったそのままで何の役になるか」というシンプルな一発勝負。

### コマンドトリガー例

- 「麻雀しよう」「配牌チャレンジ」「麻雀やって」「/mahjong」「/mj」「まーじゃん」

### ゲームフロー

1. 136 枚デッキをシャッフルして 14 枚を配牌
2. 役判定（全分解列挙による正確な判定）
3. CW（Content Warning）で結果を表示
   - `cwLabel`: 「配牌の内容」
   - `cwBody`: 14 枚の牌を 7 枚ずつ 2 行で絵文字表示
   - `text`: 役名・翻数サマリー or 流局・役なしメッセージ
4. LLM フレーミング: `generateF06Framing()` でキャラ口調の一言を先頭に付与

### 役判定ロジック

| 優先順位 | 役形 | 判定 |
| --- | --- | --- |
| 1 | 国士無双 | 13 種ヤオ九牌の有無チェック（13翻） |
| 2 | 七対子 | 7 種の対子・重複なし（2翻） |
| 3 | 基本形 | 全分解列挙で最高翻数の面子構成を採用 |

基本形の役（翻数優先で複合）:

| 役名 | 条件 | 翻数 |
| --- | --- | --- |
| 清一色 | 全牌が同一数牌種 | 6 |
| 混一色 | 字牌 + 1 種の数牌のみ | 3 |
| 対々和 | 全面子が刻子 | 2 |
| 平和 | 全面子が順子 + 雀頭が三元牌でない | 1 |
| タンヤオ | 全牌が 2〜8 の数牌 | 1 |
| 役牌（白/発/中） | 三元牌の刻子が面子に含まれる | 各 1 |

### 使用絵文字

| 種別 | 絵文字パターン | 例 |
| --- | --- | --- |
| 数牌（萬・筒・索） | `:sv_mj_{suit}_{num}:` | `:sv_mj_man_5:` |
| 字牌 | `:sv_mj_char_{id}:` | `:sv_mj_char_haku:` |

字牌 id: `east` / `south` / `west` / `north` / `haku` / `hatsu` / `chun`

### 実装ファイル

| ファイル | 内容 |
| --- | --- |
| `src/features/f06/mahjong.ts` | 新規。デッキ・配牌・全分解列挙・役判定・絵文字変換・結果テキスト生成 |
| `src/features/f06/index.ts` | `handleMahjong()` 追加 |
| `src/bot/classifier/intent.ts` | `'game-mahjong'` インテント・`MAHJONG_PATTERNS` 追加 |
| `src/bot/handlers/mention.ts` | `game-mahjong` 分岐追加（並行ゲームチェック対象外・セッションレス） |
| `src/bot/reactor/emoji-reaction-map.ts` | `'game-mahjong'` エントリ追加 |

### セッション管理

不要（ワンショット）。`GameType` ユニオンに追加していない。

## Secvier 絵文字アセット 全量棚卸し（2026-07-03 実施）

> 本番 Misskey インスタンス（`MISSKEY_HOST`）の公開API `POST /api/emojis`（認証不要、`src/misskey/client.ts` 205-217行 `fetchEmojis()` と同一エンドポイント）を実際に叩いて確認した実測値。「今すぐ必要な分だけでなく全体を確認する」目的での棚卸し。

### 全体サマリ

- インスタンス全体の登録絵文字数: **1075種**
- うち Secvier 系（`sv_` プレフィックス）: **726種**
- 現在コードでハードコードして使用しているのは **108種**（前回調査分: 数字10・トランプ52・ダイス12・麻雀34）→ **登録済みの約85%（618種）が未活用**

### カテゴリ別内訳（登録済み実数 ⇔ コード使用数）

| カテゴリ | 登録済み実数 | コード使用数 | 差分・特記事項 |
| --- | --- | --- | --- |
| トランプ | 62 | 52（`poker.ts`） | ジョーカー2種（`sv_card_joker_black/red`）・スート単体アイコン4種（`sv_card_suit_{S,H,D,C}`）が未使用。加えて各スートに標準52枚にはない4種目のランク `sv_card_{suit}_C` が存在。**判明: 「ナイト／キャバリア」で、タロットのコートカード「ペイジ」「ナイト」がトランプでは J(ジャック) に統合されている分を補完するためのカード**（用途判明済み） |

| 麻雀牌 | 41 | 34（`mahjong.ts`） | 赤ドラ3種（`sv_mj_{man,pin,sou}_5_red`）・季節牌4種（`sv_mj_season_{spring,summer,autumn,winter}`）が未使用。赤ドラは役判定への加点要素として拡張しやすい候補 |

### 主な発見・前回メモの訂正

1. **D3-6 の「4/6/8/10/12/20/100面」表記を訂正**: 実際の絵文字資産に単独の "d100" シリーズは存在しない。d100 は `d10`（一の位）＋`d10p`（十の位）の2個併記で表現するのが正しい仕様（下記 D3-6 の該当箇所も修正済み）。
2. **ダイス種別アイコン**（`sv_dice_{色}_type_d{n}`）の存在が判明。「これは d20 だよ」のような面数ラベル表示に使えそう＝ D3-6 のヨット「ダイス番号UI」案とは別軸で、面数識別演出に転用できる。
3. **英数字絵文字はアルファベットまで完備**（6色×36文字）なのに現状は数字スロットの数字部分（5色×10種）のみ使用。数字専用ではなく英数字全般の演出資産として再認識が必要。
4. **トランプの追加ランク "C"**（各スート1種、計4種）の用途が判明: 「ナイト／キャバリア」。トランプの J(ジャック) はタロットのコートカード「ペイジ」と「ナイト」が統合されたものであり、C はその欠けた「ナイト」を補うカード。**14枚コートカード構成でタロット準拠のカードゲーム/占い演出を作る場合の拡張候補**（現行ポーカーは標準52枚のみ使用のため未使用のまま）。
5. **麻雀牌の赤ドラ・季節牌7種**が未使用。麻雀配牌チャレンジの拡張（赤ドラ加点、季節牌の特殊演出）候補になりうる。
6. **色違いスートマーク8種の用途が判明**: 黒/白系（トランプ絵文字と併用するトランプ互換用）と4色系（緑/黄/赤/青、英数字図柄絵文字と組み合わせる図柄単体用）の2バリアント構成。4色系は D3-6 のヒット＆ブロウ回答ログ絵文字化案（枠色付き数字表示）に流用できそうな有力候補。

### 確認方法（再現用メモ）

```
POST https://{MISSKEY_HOST}/api/emojis
```
認証不要の公開APIで、`name` から `sv_` 始まりを抽出すればSecvier系の登録一覧が取れる。今回は一時的に `.cache/emojis_response.json`（生レスポンス）・`.cache/sv_emoji_list.txt`（`sv_` 抽出済み一覧）に保存して分析した。両ファイルはデバッグ用一時ファイルであり `.gitignore` 済みの `.cache/` 配下のためコミット対象外。

## D3-6: 既存ゲームの Secvier 絵文字活用強化案（仕様確定・milestone 昇格済み）

> 2026-07-03 発案・同日仕様確定。**実装仕様は [`milestone/2026-07-03_milestone_f06-d3-6-emoji-ux.md`](../milestone/2026-07-03_milestone_f06-d3-6-emoji-ux.md) に昇格済み**。以下は検討過程の記録として残す。

### ヒット＆ブロウ: 回答ログの絵文字化

- 現状: 判定結果はテキストのみ（`◯ヒット ◯ブロウ`）。`hitblow.ts` はテンプレート文字列を `index.ts` に直書きしており、Secvier 絵文字は未使用（数字絵文字 `SLOT_DIGIT_EMOJIS` は D3-1 数字スロットのみで使用中、`responder.ts` 210-221行）。
- 案: 予想ログをヨットのダイス表示のように、数字ごとに枠色付き絵文字で並べて表示する。ターンごとの予想履歴を1行ずつ積み上げ、右側にヒット/ブロウ数を添える（ユーザー提示イメージ）:
  ```
  1(白) 2(白) 3(青) ： 1ブロウ
  3(赤) 4(白) 5(青) ： 1ヒット1ブロウ
  3(赤) 5(赤) 6(白) ： 2ヒット
  3(赤) 5(赤) 7(赤) ： 3ヒット！正解！
  ```
- 検討事項（→ 下記たたき台で解消・要ユーザー確認）:

## D3-7: ゲーム終了後の継続コマンド対応（「もう一回」「もっと回して」）（仕様確定・milestone 昇格済み）

> 2026-07-03 発案・同日仕様確定。**実装仕様は [`milestone/2026-07-03_milestone_f06-d3-7-repeat-command.md`](../milestone/2026-07-03_milestone_f06-d3-7-repeat-command.md) に昇格済み**。数値パラメータ（TTL・回数上限）のみ実装時チューニング項目として残るが、方式自体は確定。以下は検討過程の記録として残す。
> 元々ここに含めていた「ポーカー・麻雀配牌チャレンジのセッション化（手札/手牌操作コマンド）」は別スコープのため下記の D3-8 セクションに分離した。

### 現状（調査結果）

- `src/bot/classifier/intent.ts` に「もう一回」「もっと回して」「もう一度」「またやって」等の継続発話に対応する専用パターンは存在せず、どの `*_PATTERNS` にも一致しないため `classifyIntent()` は最終的に `chat`（通常のLLM雑談応答）にフォールバックする（177-247行目、フォールバックは246行目）。
- 5ゲームのライフサイクルは2系統に分かれる:
  - **ワンショット系**（数字スロット・ポーカー・麻雀配牌チャレンジ）: `GameSessionStore` を使わず、呼ばれるたびに即結果を返すのみ。「終了状態」という概念自体がない。
  - **セッション系**（ヨット・ヒット＆ブロウ）: ゲーム正常終了（正解・確定・規定回数超過）の瞬間に `GameSessionStore.deleteSession()` でセッション行を即削除する設計（`index.ts` 328-332, 339-342, 380-383, 385-389行目）。終了直後の投稿を判定する手がかりが残らない。
- 「直前にプレイしたゲーム種別」をゲーム終了後も一定時間保持する仕組み（履歴テーブル・キャッシュ等）は `GameSessionStore` にも `mention.ts` にも存在しない。
- 結論: **ユーザーが「もう一回」と返信しても、現状は自動で同じゲームが再開されず、通常のLLM雑談応答として処理される。** ゲームを再開するには現状、明示的にゲーム名を含む発話（「スロットやって」等）が必要。

### 案: 「直近プレイ履歴」を新設して継続コマンドを解決する

- **新設ストア**（案）: `RecentGameStore`（`GameSessionStore` とは別、または同一テーブルを拡張）に `(userId, gameType, playedAt)` を保持。
- **記録タイミング**: 5ゲームいずれかの**開始時**（ワンショット系は実行時、セッション系は `handleXStart()` 時）に上書き記録する。
- **新規インテント**: `REPEAT_PATTERNS`（「もう一回」「もう一度」「またやって」「もっと(回して|やって)」「リプレイ」「全部やりなおす」等）→ `intent: 'game-repeat'` を `classifyIntent()` に追加。
- **解決ロジック**（`mention.ts` 側、既存の「アクティブセッション確認」ブロックの近くに追加）:
  1. `game-repeat` インテント検出時、まずヨット/ヒット＆ブロウ（＋後述のポーカー/麻雀セッション化後はそれらも）のアクティブセッションが無いか確認。
  2. アクティブセッションが無ければ `RecentGameStore` を参照し、有効範囲内（下記TTL/回数制限）であれば該当ゲームの `handleXStart()` 相当を呼び出す（ユーザーが元のトリガー文言を送ったのと同じ扱い）。
  3. 該当が無い場合は現状通り `chat` として処理（キャラクターが自然に「何をもう一回？」と聞き返す形になり、破綻しない）。

#### TTL・回数制限（2026-07-03 ユーザー方針を反映）

- 単純な経過時間TTLだけでなく、「**◯分間に◯回まで**」という **時間窓＋回数上限** の形式で制限する。既存の `RateLimiter`（`src/bot/ratelimit/index.ts`）の `globalPerHour`（直近1時間の投稿タイムスタンプ配列をスライディングウィンドウでフィルタしてカウント）と同じ設計思想を踏襲し、`RecentGameStore` もタイムスタンプ配列 or カウンタ方式で実装する。
- 具体的な数値（◯分・◯回）は未定。実装時にチューニングする仮パラメータとして扱う。

#### アクティブセッション優先（2026-07-03 ユーザー方針を反映）

- アクティブセッションが**ある**場合は、継続コマンドで新規ゲームを開始せず、**アクティブセッション優先**で「今終わっていないゲームを終わらせるよう誘導する」。
- 誘導メッセージ例: 「今は{ゲーム名}がまだ終わってないから、そっちを終わらせよう？」（`{ゲーム名}` はアクティブセッションの `game_type` から動的に埋め込む）。
- これにより、進行中のヨット/ヒット＆ブロウ中に「もう一回」と言われても誤って新規セッションが割り込むことがなくなる。

#### 確認ステップ（2026-07-03 ユーザー方針を反映）

- `game-repeat`（継続コマンド）そのものには確認ステップを設けない（即実行）。
- ただし、継続コマンドが**元ゲームの意図解釈を伴う操作**（後述のポーカー交換・麻雀ツモ交換の対象特定など、ヨットの振り直し対象特定と同種の操作）を含む場合は、D3-6で定めた「自然文解釈／一括指定／パーサが確信できない曖昧な入力の場合のみ確認を挟む」という**既存の例外ルールをそのまま適用**する。`game-repeat` 専用の新しい確認ルールは追加しない。

### 残タスク（数値のみ未定、方式は確定）

- TTL・回数制限の具体的な数値（時間窓・上限回数とも未定。「◯分間に◯回まで」の方式自体は確定）。
- 麻雀配牌チャレンジの結果文言に既に含まれる「もう一回どうぞ」という**誘導テキスト**（`mahjong.ts` 309行目）は、今回のシステム対応が実装されて初めて有言実行になる。他のゲームの終了メッセージにも同様の誘導文言を足すかどうかは実装時に軽く検討する。

## 絵文字アセット方針（2026-06-21 更新）

カスタム絵文字はすべて **クライアント自作のオリジナル画像** で制作・登録する。

- 既存の絵文字セット（Twemoji・OpenMoji 等）は標準的すぎるため採用しない
- 仮登録のために外部アセットを調査した（トランプ: saulspatz/SVGCards、麻雀牌: FluffyStuff/riichi-mahjong-tiles 等）が、自作の方が早いとの判断に至った
- 登録する絵文字の種類:
  - 数字図柄（1〜9）← D3-1 必須
  - トランプスート + 個別カード 52 枚 ← D3-2a 用
  - ダイス（d6 + 多面: d4/d8/d10/d12/d20/d100）← D3-2b 用（※2026-07-03棚卸しで判明: d100は`d10`+`d10p`percentileの2個併記表現。詳細は「Secvier 絵文字アセット 全量棚卸し」参照）
  - 麻雀牌 34 種（萬子・筒子・索子・字牌）← D3-4 用

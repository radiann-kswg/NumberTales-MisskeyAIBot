# F-06 拡張 — 数字ミニゲーム機能（D3）

> 作成日: 2026-06-03
> 更新日: 2026-06-23
> ステータス: **D3-1 実装済み ✅ / D3-2〜D3-5 未着手 ⏳**

---

## 概要

F-06「数字・ヌメロジーコマンド」の延長として、数字をモチーフにしたミニゲームをメンション経由で遊べる機能を追加する。
既存機能と同様に、アクティブキャラクターの個性を LLM で演出させることで、
ナンバーテールズの「数字を生きる存在」としての世界観を体験できるインタラクションを提供する。

---

## D3-1: 数字スロット

### コンセプト

1〜9 の数字を 3 桁ランダム生成し、絵文字（数字モチーフのカスタム絵文字）で演出する。
役判定の結果に対して、担当キャラクターが数字の組み合わせにコメントを添える。

### コマンドトリガー例

- 「スロット回して」「スロット」「スロットしよう」

### ゲームフロー

1. 1〜9 の数字を 3 桁ランダム生成
2. 役判定（ゾロ目 / リーチ / バラバラ等）
3. カスタム絵文字（数字図柄）で結果を表示 ← **絵文字登録完了後に実装**
4. LLM 演出: 担当キャラの口調で「この数字の組み合わせには〜」的なコメントを生成

### 役パターン（案）

| 役名               | 条件                      |
| ------------------ | ------------------------- |
| ナンバーテールズ！ | ゾロ目（例: 7-7-7）       |
| リーチ             | 2 桁同じ（例: 3-7-3）     |
| 昇順 / 降順        | 連番（例: 1-2-3 / 9-8-7） |
| バラバラ           | 上記以外                  |

### 実装メモ

- `intent: 'game-slot'` を `classifyIntent()` に追加
- 絵文字名パターン: 数字 0〜9 に対応するカスタム絵文字（インスタンス登録後に定数を定義）

## D3-2: カード / ダイスゲーム（ポーカー・ヨット系）

### コンセプト

ランダムなカードやダイスの目から役を作るゲーム。
ターン制のやり取りを SQLite セッションで管理し、担当キャラが実況コメントを生成する。

### コマンドトリガー例

- 「ポーカーしよう」「カードゲームしよう」
- 「ヨットやって」「ダイスゲームしよう」

### ポーカー仕様（案）

1. Bot が 5 枚のカードを引く
2. 役判定（ワンペア〜フラッシュ・ストレート・フルハウス 等）
3. 結果と役名をテキストで表示
4. LLM 演出: 担当キャラの口調で役に合ったコメントを生成

### ヨット（ヤッツィー系）仕様（案）

1. Bot が 5d6 を振る（`Math.random()` で代替可）
2. 役判定（ヤッツィー・フォーカインド・フルハウス 等）
3. 最大 3 ターン（振り直し選択）— セッション管理が必要
4. LLM 演出: ターンごとにキャラがリアクション

### 実装メモ

- ターン制ゲームのセッション管理は `storage/session.ts` の SQLite を拡張して保持
- `intent: 'game-poker'` / `'game-yacht'` を追加
- 同一ユーザーのゲームセッションは 1 つまで（並行ゲーム禁止）
- セッション TTL はゲーム完了 or 30 分で自動終了

## D3-3: ヒット＆ブロウ（数当てゲーム）

### コンセプト

Bot が 3〜4 桁の数字を設定し、ユーザーが数字を予想する数当てゲーム。
正解に近づくにつれて担当キャラが煽ったり励ましたりする。

### コマンドトリガー例

- 「数当てゲームしよう」「ヒットアンドブロウやって」「数字を当てて」

### ゲームフロー

1. Bot が 3〜4 桁（重複なし）の数字をランダム生成 → SQLite に保存
2. ユーザーが数字を投稿（例: 「1234」）
3. Hit 数（桁・位置とも一致）/ Blow 数（数字のみ一致）を返答
4. 正解 or 規定回数（例: 10 回）超過でゲーム終了
5. LLM 演出: 各ターンのヒット/ブロウ数に応じてキャラがコメント

### 実装メモ

- `intent: 'game-hitblow'` / `'game-guess'`（ゲーム中の予想投稿）を追加
- ゲーム中の予想投稿はメンションテキストから数字のみ抽出
- セッション TTL はゲーム完了 or 60 分で自動終了

## ゲーム機能共通の実装方針

### LLM 演出

- F-06 の既存フレーミング（`buildCharacterSystemPrompt()` 流用）でキャラ個性を反映
- アクティブキャラクターの `AbilityStats` に応じて演出の「深さ・詳しさ」を変化させる
  （既存 F-06 の設計に準じる）

### セッション管理

- ターン制ゲームの状態は `storage/session.ts` の SQLite を拡張して保持
- テーブル設計（案）:
  ```sql
  CREATE TABLE game_sessions (
    user_id TEXT NOT NULL,
    game_type TEXT NOT NULL,   -- 'hitblow' | 'yacht' | 'poker'
    state TEXT NOT NULL,        -- JSON シリアライズされたゲーム状態
    created_at INTEGER NOT NULL,
    updated_at INTEGER NOT NULL,
    PRIMARY KEY (user_id, game_type)
  );
  ```

### 意図分類

- `classifyIntent()` に `game-slot` / `game-poker` / `game-yacht` / `game-hitblow` を追加
- ゲーム中の「予想入力」は既存ゲームセッションの有無で判定する

## 拡張ゲーム案（2026-06-21 検討）

### D3-4: 麻雀牌ゲーム

麻雀牌（萬子・筒子・索子・字牌）をカスタム絵文字として活用するゲーム群。
ナンバーテールズの数字・世界観との親和性が高く、F-06 の自然な拡張になる。

#### 案 D3-4a: 牌引き占い（優先度高・実装容易）

- ユーザーが「牌を引いてください」と言うと Bot がランダムに 1〜3 枚を引いて絵文字で表示
- 引いた牌の種類別にキャラクターが占い風コメントを LLM 生成
  - 萬子 → 力・意志・挑戦
  - 筒子 → 縁・繋がり・調和
  - 索子 → 成長・試練・変化
  - 風牌（東南西北）→ 方向性・立ち位置
  - 三元牌（白発中）→ 純粋さ・覚醒・完成
- セッション管理不要（1回完結）
- インテント: `game-mahjong-draw`

#### 案 D3-4b: 手役クイズ（固定データ版）

- Bot が 14 枚の手牌を絵文字で表示し、役名を 4 択で出題
- 手役は固定データ（20〜30 パターン）で実装 — 和了判定ロジック不要
- インテント: `game-mahjong-quiz`

#### 案 D3-4c: テンパイ判断チャレンジ（難度高・後回し）

- Bot がランダム生成した 13 枚の手牌を表示
- ユーザーが「テンパイかどうか」を答える
- テンパイ検出アルゴリズムの実装が必要
- インテント: `game-mahjong-tenpai`

### D3-5: キャラ番号ルーレット

- Bot がランダムにナンバーテールズの番号を「引き」、その番号のキャラクターとの縁を演出
- CreationsDB との連携（アイデア P 実装後に本格活用可能）
- 麻雀牌の絵文字を演出に組み合わせる案あり
- インテント: `game-roulette`

## 絵文字アセット方針（2026-06-21 更新）

カスタム絵文字はすべて **クライアント自作のオリジナル画像** で制作・登録する。

- 既存の絵文字セット（Twemoji・OpenMoji 等）は標準的すぎるため採用しない
- 仮登録のために外部アセットを調査した（トランプ: saulspatz/SVGCards、麻雀牌: FluffyStuff/riichi-mahjong-tiles 等）が、自作の方が早いとの判断に至った
- 登録する絵文字の種類:
  - 数字図柄（1〜9）← D3-1 必須
  - トランプスート + 個別カード 52 枚 ← D3-2a 用
  - ダイス（d6 + 多面: d4/d8/d10/d12/d20/d100）← D3-2b 用
  - 麻雀牌 34 種（萬子・筒子・索子・字牌）← D3-4 用

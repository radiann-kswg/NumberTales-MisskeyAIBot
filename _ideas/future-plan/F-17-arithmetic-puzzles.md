## F-17A: 逆メイク10 ソルバー

### コンセプト

「メイク10」（4 つの数から 10 を作る）の逆で、**10 だけを使って 10 以外の数を作る**。
shapoco さんの漫画は「演算子が直列（+）と並列（∥）だけ」という抵抗版だが、本機能は**四則演算版を既定**にし、
演算子セットを切り替えられるようにする。

### モード（2026-09-08 決定: 2 本立て）

| モード | 演算子 | 呼び出し例 | 備考 |
| --- | --- | --- | --- |
| **四則**（既定） | `+ − × ÷` と括弧 | 「10 だけで 7 を作って」 | 7 = 10 − (10+10+10)÷10（5 個） |
| **抵抗（加算＋連分数）** | `+`（直列）`∥`（並列） | 「10kΩ だけで 7kΩ」「抵抗で 7 を作って」 | 7 = 10 ∥ (10+10+(10∥10∥10))（6 個）。連分数 7/10 = [0;1,2,3] のはしごを画像で併記 |

- 「四則＋並列」の混合セットは**作らない**（調査ノートでは検討したが、2 モードで十分と判断）
- 単位は付いていても無視する（kΩ / Ω / 円 …）。「作る対象」は正の整数。有理数（3.3 など）は抵抗モードのときだけ受ける
- 「10」以外の基数（「7 だけで 100 を作って」）も**同じコードで動く**ので受けてよい。名前だけ「逆メイク10」に固定

### アルゴリズム

- n 個の 10 で作れる値の集合 `S[n]` を `S[i] ⊕ S[n−i]` で総当たり（値は厳密有理数。`BigInt` 分数か mathjs `Fraction`）
- 目標値が最初に現れる n が最少個数。同じ n の候補は**括弧が少ない順に最大 3 通り**を画像 1 枚に複数行で組む（F-17C の `\\`）
- 探索上限は **10 個**。四則で n=10 の集合は 27.7 万値・数秒。**モードごとに 1 回計算してプロセス内キャッシュ**
  （`// ponytail: n ≤ 10 の固定上限。2 桁の番号は 9 個以内で全部作れるので当面足りる`）
- 見つからなければ「10 個までじゃ作れなかったよ」と返す（抵抗モードなら四則モードを勧める）

### 返答フォーマット（案）

```
本文: 10 だけで 7 を作るなら、5 個でいけるよ
      10 − (10 + 10 + 10) ÷ 10 = 7          ← プレーン式（併記必須）
      [画像] 同じ 5 個の別解を最大 3 行で組版（F-17C）
CW  : 抵抗モードなら 6 個: 10 // (10 + 10 + (10 // 10 // 10))
      [画像] 連分数 7/10 = [0; 1, 2, 3] の入れ子分数
```

プレーン式の並列は当面 `//` で書く（`∥` の PenchantManufacture 絵文字は将来実装予定。実装されたら差し替え）。

### キャラクターとの接点

- 「57 を 10 だけで作って」のように**キャラ番号を投げる**のが自然な使い方。発言キャラは会話相手（`ActiveCharacterStore`）のまま、
  番号が公開済みキャラと一致したら一言添える（D3-5 の `Character_JP` 流用）。新規の「番号モード」は作らない
- 抵抗セットのときは 000(チトセ) のエンジニア気質が出やすい。口上は LLM 任せで、演算子セットをプロンプトに渡すだけ

## F-17B: 手順つき素因数分解

### コンセプト

「21229 を素因数分解して」に **答え（13 × 23 × 71）＋ 手計算の手順** を返す。
手順は 1001 法（7・11・13）／ 2001 法（23・29）／ 10013 法（17・19・31）の遷移列をコードで生成する。
既存 `calculate` は mathjs なので素因数分解そのものは今でも書けるが、**手順を見せるのが新機能**。

### 呼び出し例と返答

| 入力 | 返答 |
| --- | --- |
| 「21229 を素因数分解して」 | 本文: `21229 = 13 × 23 × 71`。CW: 1001 法 `21229 → 208 → 52 → 13`（−21021, ÷4, ÷4）→ 13 で割れる ／ 2001 法 `→ 368 → 92 → 23` → 23 で割れる ／ 残り 71 は素数 |
| 「21229 は 7 で割れる？」 | 1001 法の遷移だけ返す（7・11・13 の同時判定表つき） |
| 「611 を分解して」 | `611 = 13 × 47`。1001 法 `1001 − 611 = 390 → 13` ＋ フェルマー法 `611 = 30² − 17²` を併記（√N 付近に 2 因数があるとき） |
| 「1001 は？」 | `1001 = 7 × 11 × 13`。（7・11・13 の 3 体が公開済みなら「1001 トリオ」として一言） |

### 遷移列の生成

```
入力 N, 法 M ∈ {1001, 2001, 10013}, 判定素数集合 P
1. N が M の桁数以上の間: N = 1000a + b → N' = |b − a|（1001 法）／ |2b − a|（2001 法）／ |b − 13a|（10013 法）
2. P と互いに素な小さい素数（2, 3, 5, …）で割れる限り割る
3. 3 桁以下で終端表に無ければ M − N' を試す（761 → 240）
4. gcd(N', M) を終端として提示（0 / 1 / 7 / 11 / 13 / 77 / 91 / 143 …）
```

- 表示は「21229 → 208 → 52 → 13（−21021, ÷4, ÷4）」の 1 行。手順の正しさは `test/` で
  「各ステップで mod 7・11・13（2001 法なら mod 23・29）が不変」を不変条件として固定化
- **どの法を載せるかは結果の素因数で決める**（2026-09-08 決定）: 1001 法は常に載せ、2001 法は 23・29 が、
  10013 法は 17・19・31 が素因数に**含まれるときだけ**載せる。フェルマー法は 37 以上の因数が残ったときだけ。
  手順が 2 行以上になるときは F-17C で 1 枚の画像に組む
- 37 以上の素因数は試し割り＋フェルマー法（x² − N が平方数になる x を ⌈√N⌉ から探索）で処理し、手順としては
  「フェルマー法: N = x² − y²」の 1 行だけ見せる
- 入力上限は **12 桁**（`Number.MAX_SAFE_INTEGER` 内。それ以上は「電卓を使ってくれ」と断る）

### 任意: 出題モード（後続フェーズ・当面は様子見）

**当面はリファレンスだけに留める**（2026-09-08 決定）。クイズ形式が欲しくなったら F-16 の骨格（`calc-quiz.ts`: 難易度・CW 正解発表・ストリーク・コンティニュー）をそのまま流用する。

| Lv | N の桁数 | 素因数の範囲 | 使う手法 |
| --- | --- | --- | --- |
| かんたん | 3 桁 | 2・3・5・7・11・13 | 1 の位・桁和・1001 法 |
| ふつう | 4 桁 | ≤ 13（2〜3 個） | 1001 法 |
| むずかしい | 5 桁 | ≤ 31（17〜31 を必ず 1 つ含む） | 1001 / 2001 / 10013 法 |
| 鬼 | 5〜6 桁 | ≤ 31 ＋ 37〜97 を 1 つ | ＋ フェルマー法 |

N は素因数の積から組み立てる（答えから作るので棄却が起きない）。回答は `13×23×71` / `13*23*71` / `13 23 71` / `2^3×5` を同一視。
正解発表の CW にリファレンスと同じ手順を載せる。素数番号のキャラを素因数に仕込む「番号モード」も可。

## F-17C: 数式画像描画基盤（PenchantManufacture_ImagePipeline サブモジュール）

### 目的

1 行はカスタム絵文字（既存）、**2 行以上（分数・連分数・多段式）は画像**という責務分界を Bot に持ち込む。
F-17A の連分数のはしご `\frac{1}{1+\frac{1}{2+\frac{1}{3}}}`、F-17B の多段の手順、F-16 鬼レベルの式が用途。

### 導入

| 項目 | 方針 |
| --- | --- |
| 配置 | **`_calcimage-pipeline/`** にサブモジュール追加（2026-09-08 決定。Bot 本体以外は `_` prefix、`_creations-db` と同じ扱い）。**入れ子サブモジュール `basis/`（フォント）があるので `--recursive` 必須** |
| 実行 | Node から `child_process.execFile(python, ['_calcimage-pipeline/scripts/typeset.py', expr, '-o', tmp, '--bg', 'white', '--cell', '3'])`。TS 移植はしない |
| VM | Debian 12 のシステム `python3`（3.11.2）で要件充足。`apt install libcairo2`、`python3 -m venv _calcimage-pipeline/.venv && .venv/bin/pip install -r requirements.txt`（PEP 668 対策）。`.env` に `TYPESET_PYTHON` |
| Misskey 投稿 | `MisskeyClient.uploadFile(png, name, comment)` を新設。`drive/files/create` は multipart なので Node 22 標準の `fetch` + `FormData` + `Blob` で送る（新規依存なし）。`reply()` / `post()` に `fileIds?: string[]` を追加 |

| アクセシビリティ | 本文にプレーン式を必ず併記（既存ルール）。Drive の `comment` にプレーン式を入れて alt テキストにする |
| クレジット | CC BY 4.0。画像に埋め込まれるが、**Bot プロフィールに「数式画像: PenchantManufacture (RadianN_kswg, CC BY 4.0)」を明記**（同リポジトリの運用ルール）。投稿本文には毎回入れない（2026-09-08 決定: プロフィール固定） |
| キャッシュ | 同じ式は `.cache/typeset/<sha1>.png` を再利用（`.cache/` は git 管轄外） |

## やらないこと（スコープ外）

- LLM による計算・手順生成 — **すべてコード**。キャラの一言だけ LLM
- 逆メイク10 のクイズ化 — リファレンスとして出す。遊びたければ人が自分で数を投げればよい
- 回路図の描画（SVG）— テキスト記法と連分数画像で代替
- 階乗・平方根・累乗・連結（`1010`）などの拡張演算子、四則と並列の混合モード — 2 モードで止める。増やすと探索空間が爆発する
- 式の絵文字描画（`∥` など未収録字の PenchantManufacture 絵文字）— 将来実装予定。当面は画像パイプラインで出す
- 37 以上の素数の同時判定法（記事も未執筆）— フェルマー法と試し割りで受ける
- ImagePipeline の TypeScript 移植 — Python を spawn する

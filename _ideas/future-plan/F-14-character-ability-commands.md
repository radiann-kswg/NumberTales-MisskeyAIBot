## 概要

各ナンバーテールズの `Hobby` / `SpecialSkill` / `NumerospecAbout`（創作DB）に根ざした
**キャラクター固有コマンド**を提供する機能。

例:

- 「**78(ナナハ)に占ってもらう**」→ タロット占い（趣味: タロットカード）
- 「**44(シトシ)とヨットで対決**」→ ヨットハードモード対戦（特技: 出目操作／趣味: アーケード巡り）
- 「**33(ミサ)に調べ物してもらう**」→ 知識レファレンス（Numerospec: 全域の知識・技能を習得。
  発動条件「オンライン状態」をそのまま利用制約ギミックに転用できる）

---

## 呼び出しUX（確定方針）

**一時ゲスト召喚方式＋キャラ別親密度**のハイブリッド。

1. 固有コマンドは**アクティブキャラを変更せず**、召喚されたキャラが「ゲスト」として
   その応答のみを担当する（`ActiveCharacterStore` の状態は不変）。
2. ただし召喚・利用のたびに**そのキャラとの親密度（アフィニティ）が蓄積**され、
   親密度レベルに応じて固有コマンドの上位ティアが解放される。
   → 「呼び出しは軽く、絆は深く」。切り替えの手間なしに、キャラごとに仲良くなる動機が生まれる。

### 親密度（アフィニティ）設計案

- 既存の F-12B 信頼度（ユーザー単位のグローバル値）は**そのまま維持**し、
  別テーブル `character_affinity (user_id, char_num, points, ...)` を新設する（移行不要・低リスク）。
- **加算契機（固有コマンド外も対象）**:
  - 固有コマンド利用: 1回 +n（**1日あたり上限あり**でスパム加算防止）
  - 該当キャラを**アクティブキャラとして選択中**の活動全般:
    - タスク完了（F-12B のタスク完了ポイント加算時）
    - schedule 通知の確認・会話ボーナス（1日1回）
  - 実装方式: F-12B 信頼度の加算処理に**共通フック**を設け、加算時に
    `ActiveCharacterStore.resolve` でアクティブキャラを解決して同キャラの
    アフィニティにも同時加算する（F-12B改修「通知キャラ＝会話相手キャラ解決」の仕組みを流用）。
- ティア解放の例:

| ティア | 例（78ナナハ） | 例（44シトシ） | 例（33ミサ） |
| ------ | -------------- | -------------- | ------------ |
| Lv.1（初期） | 1枚引きタロット | ヨット通常対決 | 簡単な調べ物 |
| Lv.2 | 3枚スプレッド | ハードモード（出目操作口上） | 深掘り回答＋出典風フレーバー |
| Lv.3 | 限定演出・特別口上 | 連戦モード・戦績口上 | 「オフライン」時の特別対応 |

## アーキテクチャ骨子

- **能力レジストリ方式（1キャラ1ファイルのプラグイン形式）**:

  ```
  features/char-abilities/
    index.ts          # レジストリ（abilities/ を自動集約・トリガーマッチング）
    types.ts          # AbilityDefinition インターフェース定義
    _template.ts      # コピー用テンプレート（記入例コメント付き）
    abilities/
      078-tarot.ts    # 1キャラ1ファイル（Numゼロ埋め3桁-能力名.ts）
      044-yacht-duel.ts
      033-research.ts
  ```

  - DBフィールドは**フレーバー文の素材**として参照。**ゲームメカニクス自体は user 監修のレジストリで定義**
    （→「未公開設定の自動生成禁止」に抵触しない）。

### 追加実装の2トラック（user が加担しやすい形式）

| トラック | 対象 | 追加時の作業 |
| -------- | ---- | ------------ |
| **宣言型（LLMフレーバー型）** | 占い・調べ物など「キャラプロンプトで一発応答」する能力 | `_template.ts` をコピーし、トリガー語・参照DBフィールド・口上テンプレ・ティア定義を**記入するだけ**（ハンドラは共通実装が処理） |
| **コード型（ゲーム型）** | `GameSessionStore` 連携が必要な対戦・セッション系 | 上記に加えハンドラ関数を実装 |

### 品質担保: レジストリ自己検証テスト

`npm test` で全定義ファイルを読み込み、以下を一括チェックする:

- トリガー語の衝突（キャラ間・既存インテントとの競合）
- `Num` が創作DBに実在するか（`CreationsDBClient` 経由）
- ティア定義の抜け・型不整合

**追加フロー**: テンプレをコピー → 記入 → `npm run typecheck` ＋ `npm test` → `develop` へ PR。
- 意図分類に `character-ability` ブランチを追加（「NNに〜してもらう」「NNと〜で対決」等）。
- ゲスト応答は該当キャラの `buildCharacterSystemPrompt()`（DB生成ロールプレイプロンプト二層）で生成。
- 対戦系は `GameSessionStore`＋D3-7 継続コマンド（「もう一回」）にそのまま乗せる。
- 演出は D3-6 の桁根カラー則・Secvier 絵文字を流用。

## 78(ナナハ) タロット占い: カードアセット方針（2026-07-20 決定）

**マルセイユ版・小アルカナのみ**で実装する。

- **アセット**: 既存 Secvier トランプ絵文字 52枚＋ナイト札 `sv_card_{suit}_C` 4種で
  **小アルカナ 56枚（14枚×4スート）が完全に揃う**（2026-07-03 棚卸しで用途判明済みの未活用資産を活用）。
- **スート対応**: クラブ→棒(ワンド)／ハート→杯(カップ)／スペード→剣(ソード)／ダイヤ→金貨(コイン)
  の標準対応。4色スートマーク（`sv_suit_*` 4色系）をスートテーマ演出に添える案あり。
- **占いとしての整合**: マルセイユ版小アルカナは元来数札（ピップカード）でトランプと系譜的に同根。
  小アルカナ＝日常の具体的事柄を読む札のため、Bot の日常占い用途に適合
  （ナナハの口上「日々の機微を読む」として演出）。
- **意味データ**: 牌引き占い（D3-4a）と同方式 — 意味テーブルはコード側固定（user 監修）、
  文面のみ LLM 生成。
- **大アルカナ 22枚**: 当面は実装せず、**アフィニティ上位ティア（Lv.3）の拡張フックとして温存**。
  カスタム絵文字は別創作タイトル**「運命線探偵78」**（https://fateline-investigator78.com/characters.html）
  由来のものを将来的に登録検討中（user 方針・2026-07-20）。登録され次第、Lv.3 解放の特別演出として
  「大アルカナが引けるようになる」形で組み込む。英数字絵文字等による代用表示は行わない
  （タロットは絵柄が本質のため）。

## bot-spec 残タスク「AbilityStats / SpecialSkill 演出差の本格実装」との対応（2026-07-20 追記）

本機能は bot-spec 残タスクの演出差実装を段階的に回収する。3段階に分割:

| 段階 | 内容 | 実装先 | 規模 |
| ---- | ---- | ------ | ---- |
| ① プロンプト注入 | `AbilityStats` のランク（Speed S / Communication D 等）を言語化して `buildCharacterSystemPrompt()` の専門性セクションへ追加（例: 「反応は機敏」「口数は控えめ」）。`hideText`（非公開）項目は**注入しない** | 既存 `prompt-builder.ts` の小改修（F-14 と独立に着手可） | 小 |
| ② 口上・リアクション反映 | F-06 ゲームの口上・結果フレーミングにランクを反映（Technic 高ランクはヨットで玄人っぽい一言等） | 既存 `responder` の小改修 | 小〜中 |
| ③ コマンド化（本丸） | `SpecialSkill` を固有コマンドとして機能化・ティア演出 | 本機能（F-14） | 大 |

①②は F-14 を待たず既存機能の改修として先行実装できる。

## 概要

F-11（誕生日お祝い）と F-13（季節・記念日イベント投稿）は、
いずれも「日付ベースの自動発火」機能として共通設計できるため合算して仕様化する。

---

## F-11: 誕生日お祝い

### 対象の誕生日 (3種類)

| 対象 | 情報源 | 内容 |
|-----|-------|------|
| **Misskeyユーザー** | セッションDB（ユーザー登録） | フォロワーの誕生日をお祝い |
| **ナンバーテールズキャラクター** | `_creations-db`（キャラデータ） | 各個体の誕生日 |
| **他タイトルの創作キャラクター** | `_creations-db`（タイトル横断） | 百花繚乱研究所の他作品キャラ |

> **開発記念日** もF-13のカレンダーイベントとして管理する。

---

### F-11-A: Misskeyユーザーの誕生日お祝い

#### 登録フロー

```
ユーザー: 「私の誕生日は7月7日です」「誕生日登録したい、6/15生まれ」
→ Bot: 月・日を抽出してDBに保存
→ 担当キャラ: 「覚えたよ！〇月〇日に必ず声をかけるね。」
```

> **年は保存しない**（プライバシー配慮。年齢に関する推測も行わない）

#### DB設計

```sql
CREATE TABLE IF NOT EXISTS user_birthdays (
  user_id  TEXT PRIMARY KEY,
  month    INTEGER NOT NULL,   -- 1〜12
  day      INTEGER NOT NULL    -- 1〜31
);
```

#### お祝いフロー（誕生日当日）

```
[毎朝スケジューラー] 今日が誕生日のユーザーを確認

[担当キャラクターが個別メンション]
本文: 「〇〇さん、誕生日おめでとう！:tada:  
       今日という特別な日に :cake:」

CW（詳細）:
「誕生日は、あなたの人生の新しいサイクルが始まる日。
 エンジェルナンバー〇番（誕生月日を数秘変換）のエネルギーが
 今日のあなたに宿っているよ。[ヌメロジーワンポイント]」
```

**差別化ポイント**: 誕生月日からエンジェルナンバー / ライフパスナンバーを即計算して添える（F-06/F-10連携）。

### F-11-B: ナンバーテールズキャラクターの誕生日

#### 情報源

`_creations-db/data/Works_NumberTales/DataBases/db_Primary.json` の
誕生日フィールドを参照する（フィールド名は実装時に確認）。

#### 投稿フロー

```
[毎朝スケジューラー] 今日が誕生日の個体を確認（DBから照合）

[担当キャラクターまたはチトセが自発投稿]
例（000チトセが78(ナナハ)の誕生日を祝う）:
「今日は78(ナナハ)の誕生日だよ。
 タロットの女神、今日もその透明感を存分に発揮してほしい。
 ハッピーバースデー、ナナハ。:sparkles:」
```

> **担当キャラクターが本人と同一の場合**: 本人が「私の誕生日です」的な自己紹介投稿をする演出でもよい。

#### 注意点

- 誕生日が非公開設定のキャラクターは対象外にする
- 誕生日の「なし」「不明」は飛ばす

### F-11-C: 他タイトルの創作キャラクター誕生日

`_creations-db` が複数タイトルのキャラを管理している場合、
ナンバーテールズ以外のタイトルにもお祝い投稿を行う。

> 実装詳細は creations-db のデータ構造拡充後に詳細化する。

## F-13: 季節・記念日イベント投稿

### カレンダーイベント一覧（案）

| 日付 | イベント名 | 投稿コンセプト |
|-----|-----------|-------------|
| 1/1 | お正月 | 新年の数字占い・今年のナンバーテールズ的一文字 |
| 2/3 | 節分 | 「厄を払う数字は…」担当キャラ豆まき演出 |
| 2/14 | バレンタイン | 担当キャラからフォロワーへメッセージ |
| 3/14 | π(パイ)の日 | 3.14…の数字をネタにした数学トーク |
| 3/21 | 春分の日 | 季節の変わり目・サイクルの数字（9や1）の話 |
| 4/1 | エイプリルフール | 数字にまつわる「嘘」ネタ投稿（軽め） |
| 7/7 | 七夕 | 7の数字の意味「精神性・直観」と星に願う演出 |
| 11/11 | ポッキーの日 / エンジェルナンバーの日 | **ゾロ目の1111は特別なエンジェルナンバー！** |
| 12/25 | クリスマス | 2+5=7「完成の数字で締めくくる一年」 |
| 12/31 | 大晦日 | 9のエネルギー「サイクルの完結・手放しと再生」 |

#### ナンバーテールズ独自の数字イベント（案）

| 日付 | イベント名 | 内容 |
|-----|-----------|------|
| Bot誕生日 | 開発記念日 | 「私が生まれた日」（000チトセ視点） |
| 各プロジェクト記念日 | 百花繚乱研究所記念日 | クライアントが日付を指定して設定 |

---

### DB設計: カレンダーイベントテーブル

```sql
CREATE TABLE IF NOT EXISTS calendar_events (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  month       INTEGER NOT NULL,       -- 月
  day         INTEGER NOT NULL,       -- 日
  event_name  TEXT NOT NULL,          -- イベント名
  event_type  TEXT NOT NULL,          -- 'seasonal' | 'character' | 'anniversary'
  template    TEXT,                   -- LLMへのヒント（省略時はLLMが自由生成）
  enabled     INTEGER DEFAULT 1       -- 0=無効化可
);
```

> 静的なイベントは起動時にデータ投入、Bot誕生日等はクライアントが手動追加。

---

### 投稿フロー

```
[毎朝スケジューラー起動時]
→ calendar_events テーブルで今日の日付を照合
→ 該当イベントがあれば担当キャラクターが自発投稿を生成・送信
→ 誕生日（F-11）のチェックと同時に実行（スケジューラーを共有）
```

---

## 共通スケジューラー設計

F-11 と F-13 は「毎朝1回実行」で統合できる。既存の F-02（時間帯別自発投稿）のスケジューラーに追記する形が自然。

```typescript
// 朝スロット（既存 F-02）の実行時に誕生日・イベントチェックを追加
async function morningSchedule(): Promise<void> {
  await checkBirthdays();        // F-11: 誕生日チェック
  await checkCalendarEvents();   // F-13: イベントチェック
  await generateMorningPost();   // F-02: 通常の朝の自発投稿
}
```

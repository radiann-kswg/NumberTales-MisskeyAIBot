## Stage B: 計算仕様（枡本つづり式）

### ヘボン式ローマ字変換（実装の本体）

`src/features/f06/hepburn.ts`（新規）にかな→ヘボン式変換器を実装する。例外規則:

- 長音「お」: 末尾のみ `O` 表記（みそのお→MISONOO / おおの→ONO / こおり→KORI）
- 長音「う」: 常に `U` を入れない（さとう→SATO / ゆうか→YUKA / こうち→KOCHI）
- 漢字が切り替わる箇所は長音扱いしない（まつうら→MATSUURA / ひろおか→HIROOKA）
  → **かな入力だけでは境界を判定できない。** 後述「入力形式と漢字境界の扱い」を参照
- 「ー」は省略（ニーナ→NINA）。ただし「イ」「ィ」は表記（ニイナ→NIINA）
- 「っ」は子音重ね。ただし CH の前は T（ほっち→HOTCHI）
- 「ん」= N。ただし B・M・P の前は M（なんば→NAMBA）
- ふ=FU / つ=TSU / ず・づ=ZU

**単体テスト**: 上記の実例（御園生・大野・佐藤・松浦・ほっち・なんば等）を全ケース網羅すること。

### 数値化とナンバー算出

ローマ字各文字をピタゴラス式対応表（A=1..I=9, J=1.. の標準表）で数値化し:

| ナンバー | 算出 |
| -------- | ---- |
| D（ディスティニー） | 全文字合計を縮約 |
| S（ソウル） | 母音（A/I/U/E/O）のみ合計を縮約 |
| P（パーソナリティ） | 子音のみ合計を縮約（D−S でも可） |
| IT（インテンシティ） | 最多出現数 |
| LL（ライフレッスン） | 未出現数 |
| M（マチュリティ） | LP + D（ゾロ目はそのまま加算して縮約） |
| B（バースデー） | 誕生「日」のみ縮約（11日・22日はそのまま） |

- 11・22・33 のゾロ目は縮約ストップ（Stage A の LP と同一規則・既存実装を流用）

### 入力形式と漢字境界の扱い（2026-07-20 決定）

長音の短縮可否が**漢字境界に依存する**ため、漢字とかなの両方を受け取る。

| 入力形式 | 例 | 扱い |
| -------- | -- | ---- |
| 漢字＋かな（推奨） | `松浦 まつうら` | 境界判定に漢字を利用（下記の二段構え） |
| かなのみ | `まつうら` | 境界不明として扱う |
| ローマ字直接 | `MATSUURA` | ヘボン変換をスキップ |

> **⚠️ 漢字を受け取っても境界は自動決定できない。**
> 「松浦 → まつ/うら」のような漢字とかなの対応付け（アライメント）は、
> 「五十嵐 → いがらし」のように単純分解できない例があるため、辞書なしでは解けない。
> よって**曖昧になる場面だけを追加確認する**二段構えとする。

1. **長音候補（`おお` / `おう` / `うう` / `ええ` / `いい` の連続）を含まない場合**
   → 境界は結果に影響しないため、かなをそのまま変換する（**大多数のケース**）
2. **長音候補を含む場合のみ**
   → 区切り入力を促す（`まつ／うら`）か、両解釈（`MATSUURA` / `MATSURA`）を提示して選ばせる

**判定が必要な実例**: まつうら（MATSUURA / MATSURA）・ひろおか（HIROOKA / HIROKA）・
みそのお（MISONOO）・おおの（ONO）・こおり（KORI）

- **個人情報**: 漢字を受け取っても**計算のみで破棄し永続保存しない**（既存方針どおり）
- Stage C-1 姓名判断は画数計算に漢字が必須のため、**入力形式を揃えられる利点**がある

### 制約（重要）

- **名前は個人情報のため永続保存しない**（計算のみ行い破棄。既存方針に従う）
- 解釈文はサイトから転載せず、**user 監修のオリジナル文**をプールデータとして用意
- 計算方式の参照元クレジットをドキュメント（本ファイル＋README 機能説明）に記載

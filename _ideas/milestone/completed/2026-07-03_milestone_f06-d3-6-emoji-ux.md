## 概要

Secvier 絵文字アセットの全量棚卸し（2026-07-03 実施、登録済み726種のうちコード使用中は108種のみと判明）を受けて、
既存3ミニゲーム（ヒット＆ブロウ・ヨット・汎用ダイスロール `nDm`）の表示・操作性を、未活用の絵文字資産を使って改善する。
新規ゲームの追加ではなく、既存ゲームの UI/UX 強化が目的。

---

## 1. ヒット＆ブロウ: 回答ログの絵文字化

### 仕様

- **数字タイル**: 全桁を `sv_hakuji_{digit}`（白磁・中立色）で統一表示。`SLOT_DIGIT_EMOJIS`（`responder.ts` 210-221行、数字スロット専用の数字ごと固定色）とは別セットとして完全に切り離す。
- **状態マーカー**: 数字タイルの直前に1桁ずつ `:マーカー::数字:` の形で付与。
  | 状態 | マーカー絵文字 |
  | --- | --- |
  | ヒット | `sv_suit_heart_red`（4色系・赤） |
  | ブロウ | `sv_suit_spade_blue`（4色系・青） |
  | 非該当 | `sv_suit_heart_white`（黒白系・白） |
- **ログ格納**: 麻雀配牌チャレンジ（`mahjong.ts`）と同様に CW 形式で格納する。
  - `cwLabel`: 「◯回目の予想」
  - `cwBody`: ここまでの全予想ログ（1ターン1行、マーカー付き数字タイル＋ヒット/ブロウ数）
  - `text`: 最新ターンのヒット/ブロウ数のみの短い要約（CW を開かなくても結果が分かるように）
- **セッション拡張**: `HitBlowState` に `guessHistory: { guess: string; hits: number; blows: number }[]` を追加し、ターンごとに追記。

### 表示イメージ

```
1(白) 2(白) 3(青) ： 1ブロウ
3(赤) 4(白) 5(青) ： 1ヒット1ブロウ
3(赤) 5(赤) 6(白) ： 2ヒット
3(赤) 5(赤) 7(赤) ： 3ヒット！正解！
```

## 2. ヨット: ダイス識別性・振り直し指定の改善

### ダイス番号UI

- Secvier 絵文字には位置番号専用絵文字が無いため、標準の丸数字（①②③④⑤）をテキストとしてダイス絵文字の直下または直後に添える（新規絵文字登録は不要）。
- ダイス種別アイコン（`sv_dice_hakuji_type_d6` 等）をメッセージ冒頭に添えて「5d6のヨットだよ」という文脈表示も追加する。

### 出目ベース自然文の振り直し指定

- 「Nの目を振り直し」（出目Nのダイスを振り直し対象にする）と「Nの目以外を振り直し」（出目Nのダイスをキープし残りを振り直し対象にする）の2パターンに対応する。
- 位置指定（「1番」「①」等）と出目指定が同一文に混在した場合は、**両方の指定を和集合（OR）で振り直し対象に加える**（例:「1番と3の目を振り直し」→ 1番目のダイス ∪ 出目が3のダイス全て）。

### 振り直し前の確認ステップ（条件付き採用）

毎回は挟まない。以下の判定で分岐する:

| ケース | 挙動 |
| --- | --- |
| 位置番号での明示指定（「1番と3番を振り直し」等） | 即実行 |
| 自然文プロンプト由来の解釈結果（出目ベース指定など） | 確認を挟む |
| 「全部」「全て」のような一括指定 | 確認を挟む |
| その他パーサが意図を確信できない曖昧な入力 | 確認を挟む |

- 確認メッセージ例: 「①③のダイスを振り直すね。いい？」
- `YachtState` に `pendingReroll: number[] | null` を追加。「いいよ／はい／OK」等の肯定で実行、「やめとく／待って」等の否定でキャンセルして再入力を促す。
- 曖昧性判定ロジック（パーサ側で「確信度」を返すか、指定パターンで機械的に分岐するか）は実装時に詰める。

> **注**: この「確認ステップの採用可否判定ルール」は D3-7（継続コマンド）でも共通適用される（意図解釈を伴う操作全般の既存ルールとして扱う）。

## 3. 汎用ダイスロール（`nDm` コマンド）: 出目の絵文字表示

### 仕様

- **対応面数**: d4/d6/d8/d10/d12/d20 は `sv_dice_{色}_d{n}_{face}` 命名で5色（紅玉・砂金・翠玉・星幽・白磁）すべて登録済みのため、そのまま出目絵文字を表示する。
- **d100**: 単独面が存在しないため `d10p`（十の位アイコン: 00/10…90）→ `d10`（一の位アイコン: 0〜9）の順で2個連結表示し、末尾に合成した合計値をテキストで併記する。
  例: `:sv_dice_hakuji_d10p_70::sv_dice_hakuji_d10_3: → 73`
- **対応外の面数**（上記6種＋d100 以外、例: 3面・7面・任意のカスタム面数）: 出目絵文字が無いため、数字図柄絵文字（`SLOT_DIGIT_EMOJIS` または英数字絵文字）を桁ごとに並べるスコアボード風の代替表示にフォールバックする。
- **色（確定）**: 担当キャラクターのイメージカラーに5色を紐付け、アクティブキャラに応じて変える。既存 F-06 の「アクティブキャラクターの個性を反映」方針と一貫。
- **複数個ロール**: ダイスごとに絵文字を横並び表示し、末尾に `= 合計値` を添える（ヨットの `diceEmojiLine()` と同じ見せ方）。個数が多い場合（閾値: 10個超）は CW 格納 or 絵文字表示を省略してテキストのみにフォールバックする。
- **面数ラベル**: ロール結果の冒頭にダイス種別アイコン（`sv_dice_{色}_type_d{n}`）を添えて何面ダイスかを明示する。

## 残タスク

- **キャラ⇔ダイス色の対応表**: 5色（紅玉・砂金・翠玉・星幽・白磁）と各担当キャラクターのイメージカラーの対応が未定義。`_creations-db` のキャラクターデータ参照、またはユーザーへの確認が必要（実装着手前に整理する）。

## 実装ステップ

1. キャラ⇔ダイス色の対応表を確定（残タスク解消）
2. ヒット＆ブロウ: `HitBlowState.guessHistory` 追加・CW格納ロジック実装
3. ヨット: 丸数字UI・ダイス種別アイコン表示追加
4. ヨット: 出目ベース自然文パーサ追加（位置指定との和集合ロジック含む）
5. ヨット: `pendingReroll` 確認フロー追加
6. 汎用ダイスロール: d4/d6/d8/d10/d12/d20 と d100（d10p+d10）の絵文字表示追加
7. 汎用ダイスロール: 対応外面数のフォールバック表示追加
8. `npm run typecheck` で確認

# バグレポート: タスク追加の失敗 / タスク追加時のロールプレイ劣化 — 不具合報告

> 作成日: 2026-07-05
> ステータス: **対応済み** ✅（2026-07-05、実機ログとの突き合わせは未実施）
> 対象機能: F-12・F-12B（タスク＆スケジュール管理） / キャラクタープロンプト（ロールプレイ口調）
> 出典: 実機（[@APHR_NTs](https://radiann6631.net/@APHR_NTs)）運用中に受領したバグ報告

## 対応内容（2026-07-05）

- **タスク追加ができていない**: `src/bot/classifier/intent.ts` の意図分類で、`TASK_LIST_PATTERNS`（「進捗」）・
  `TASK_DONE_PATTERNS`（「完了」）が語単独でもマッチする広いパターンだったため、「進捗管理のためにタスク登録して」
  のような追加依頼が `task-list`/`task-done` に誤分類され、タスクが登録されないまま雑談応答へフォールスルーして
  いた。`TASK_ADD_PATTERNS` の判定順を `task-list`/`task-done`/`task-cancel` より先に変更し、明示的な追加トリガー
  語がある場合はそちらを優先するよう修正（[intent.ts](../../../src/bot/classifier/intent.ts)）。
- **タスク追加時だけロールプレイが中途半端**: `src/bot/handlers/mention.ts` のタスク登録確認メッセージ生成プロンプトに、
  他の応答経路（F-06結果・挨拶・キャラ切替等）と同様の「あなたのキャラクターとして自然に」という明示指示が
  欠けていたため修正。
- 実機ログと証跡ノート本文の突き合わせによる原因確定は未実施のため、実運用で再発した場合は追加調査が必要。

## 想定原因の切り分け余地（未確定）

以下は調査開始時の切り分けの当たりであり、原因の断定ではない。実機ログとノート本文の突き合わせで確定する。

**1. タスク追加ができていない**

- 追加インテントの分類漏れ（`src/bot/classifier/intent.ts`）— 追加の意図が別インテント（例: `chat`）へ
  流れていないか。
- LLM による日時・タスク内容抽出の失敗（`src/features/task/index.ts`）— 抽出結果が空・不正で登録に至らないか。
- 永続化・上限まわり（`src/storage/task.ts`）— 同時10件上限に達している等で追加が弾かれていないか。
- レートリミット等による早期リターン（`src/bot/handlers/mention.ts`・`src/bot/ratelimit/`）で追加処理まで
  到達していない可能性。

**2. タスク追加時だけロールプレイが中途半端**

- タスク追加応答の生成経路が、通常会話と異なるプロンプト構築を通っていないか
  （`buildCharacterSystemPrompt` / タスク系ハンドラの応答整形）。
- タスク処理分岐で定型テンプレート寄りの応答になり、キャラクター口調が薄まる経路の有無。
- 「タスク追加時だけ」という限定条件から、タスク系ハンドラ固有の応答整形が疑わしい。

> 上記は仮説の列挙にとどめる。実装着手時にはユーザー確認・実機ログ照合を挟み、確定した原因のみを
> 該当機能の実装／milestone へ反映する。

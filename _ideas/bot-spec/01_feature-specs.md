## F-01: ゆる会話（メンション応答）

### 概要

ユーザーからメンション（`@000chitose`など）を受けた際に、000(チトセ)として短文で返答する。

### 動作仕様

- 返答文字数: **100文字以内**（超える場合はCWで折りたたむ）
- 返答スタイル: 中性的・フレンドリー・若手エンジニア口調
- カスタム絵文字を1〜2個付与

### 処理フロー

```
ユーザーのメンション受信
  → 意図分類（ルールベース or 軽量AI）
  → 挨拶/質問/創作相談 などにカテゴリ分け
  → カテゴリに応じた返答生成
      ├─ 挨拶     → 定型返答（ルールベース）
      ├─ 雑談     → LLM生成（短文）
      └─ 創作相談 → LLM生成 + CW折りたたみ
```

### 口調例

> 「なんか用かな？私でよければ聞くよ :chitose_wave:」
> 「それ、面白い設定だね。もう少し詳しく教えてくれるかい？」

## F-02: 深夜雑談モード

### 概要

時間帯（23:00〜5:00）に応じてBot側からの自発投稿や浮上頻度を変化させる。深夜帯は静かめ・ほっこりトーンに変化。

### 動作仕様

| 時間帯   | 浮上頻度 | トーン                   | 自発投稿テーマ               |
| -------- | -------- | ------------------------ | ---------------------------- |
| 朝〜昼   | 通常     | 元気・テキパキ           | 軽い挨拶、作業開始の声かけ   |
| 昼〜夕方 | 低め     | 事務的・落ち着き         | —（基本は返答のみ）          |
| 深夜     | 控えめ   | ほっこり・哲学的・眠そう | 「お茶どうぞ」「作業お疲れ」 |

### 自発投稿例（深夜帯）

> 「深夜の工房、静かだね。作業中の君へ、お茶をどうぞ :tea:」
> 「夜更かしは体に堪えるよ…でも、わかる。私もそういう夜がある」

### 制約

- 深夜帯の自発投稿は **1〜2時間に1回** 上限
- リプライ・RTへの過剰な反応は深夜帯は抑制
- 自発投稿の公開範囲は **パブリック投稿**（`visibility: public`）を原則とする
  - ローカルTL・グローバルTLにも流れ、フォロワー外のユーザーにも届きやすい
  - フォロワー数が少ない期間にも投稿が目に留まりやすいよう、露出を優先する方針に変更（2026-05-29 仕様変更）
  - 返信（reply）は引き続き `visibility: home`。週次担当 Poll ノート・そのセルフリノートも `visibility: public`

## F-03: 創作支援（壁打ちモード）

### 概要

ユーザーからの創作相談（キャラ設定・お題・世界観）に対して、000(チトセ)として壁打ち相手になる。

### 対応する創作相談の種類

| 種別           | 内容                                                               | 応答方式              |
| -------------- | ------------------------------------------------------------------ | --------------------- |
| お題生成       | 「お絵描きお題くれ」「創作テーマ欲しい」など                       | LLM生成（短文 or CW） |
| キャラ設定補助 | 「こういうキャラを考えてるんだけど」「設定の穴埋めて」など         | LLM生成（CW必須）     |
| 世界観深掘り   | 「この世界の技術レベルって？」「ナンバーテールズとの絡みは？」など | LLM生成（CW必須）     |

### 壁打ちの口調例

> 「面白い設定だね。でも、その子の動機がちょっとぼんやりしてる気がするんだ。どんな過去があるんだろう？」
> 「お絵描きお題、いくよ。『雨宿りする二人のナンバーテールズ』どうかな :rain:」

### 制約

- **未公開のナンバーテールズ設定・台詞をBotが自動生成しない**（ユーザーが手動で与えた情報のみ参照）
- 著しく性的・反社会的なテーマは応答拒否

### ハッシュタグ監視

原則として **ハッシュタグ監視は行わない**。以下の例外のみ対応する。

| 種別                     | 対象タグ例                                        | 条件                                 |
| ------------------------ | ------------------------------------------------- | ------------------------------------ |
| NT本作直接関与タグ       | `#ナンバーテールズ` `#ナンバーテールズの主人より` | 全体監視（フォロー外も含む）         |
| 許可アカウントのタグ投稿 | 任意のタグ                                        | コマンド・権限付与済みアカウントのみ |

- 許可アカウントの管理方法・権限付与コマンドの仕様は別途定義する
- 全体監視の実装: `globalTimeline` チャンネル購読 + LLM 二次フィルタリング（`respect` / `neutral` / `disrespect`）
  → 実装詳細: [milestone/2026-06-03_milestone_global-tl-tag-detection.md](../milestone/2026-06-03_milestone_global-tl-tag-detection.md)

## F-04: リアクション・エモパシー

### 概要

TLのノートを観測し、感情文脈を読み取ってカスタム絵文字リアクションや短いリプライを行う。

### 動作仕様

- **リアクション**は感情分類（喜/悲/驚/疲/etc.）に基づき固定辞書から選択
- 感情分類は **LLM 駆動化予定**（ハイブリッド方式）:
  - 挨拶系（おはよう・おやすみ・ただいまなど）は正規表現で先行判定してリアクション送信
  - それ以外は LLM に投稿テキストを渡してカテゴリを 1 単語で返させる
  - 判定に迷う投稿・否定的文脈は `skip` を返させてリアクションしない
  - 詳細: [milestone/2026-06-03_milestone_f04-llm-reaction.md](../milestone/2026-06-03_milestone_f04-llm-reaction.md)
- **リプライ**はカテゴリ別の短文テンプレートを用いる（LLM不使用）
- 同一ユーザーへの連続リアクションは **1時間以内に1回** 上限

### フィルタリング基準

**「内容が明確で、想定するリアクションを送ることに適切な投稿のみ」** を対象とする。
誤ったリアクションはトラブルの原因になるため、判定に迷う投稿はリアクションしない（スキップを優先）。

| 判定   | 投稿の例                                       | 対応               |
| ------ | ---------------------------------------------- | ------------------ |
| 適切   | 完成報告・作業完了・お疲れ挨拶・喜びの報告など | リアクション送信   |
| 不適切 | 感情が複雑・怒り・悩み・文脈が不明確な投稿など | スキップ（無反応） |

- 判定スコアリングの具体的な閾値は実装フェーズで定義する

### 感情カテゴリと絵文字対応例（要カスタマイズ）

| カテゴリ | 代表絵文字例                                                                |
| -------- | --------------------------------------------------------------------------- |
| 喜び     | `:yatta:` `:blobhappy:`                                                     |
| 疲労     | `:otsukaresama:` `:blobsleep:`                                              |
| 悲しみ   | `:yoshi:` `:blobsad:`                                                       |
| 驚き     | `:blobsurprised:`                                                           |
| 創作中   | `:art:` `:blobpopcorn:`                                                     |
| 共感     | `:murisinaide_aphrnts20:` など（sympathy カテゴリ：落ち込み・悩みへの共感） |

### 注意事項

- リアクション対象は **フォロイーのノート**（homeTimeline）を基本とする
- グローバルTLへのリアクションは D2 実装後に追加（ナンバーテールズ関連タグ投稿に限定）
- 「過剰にリアクションするBot」と認識されないよう頻度制御を徹底

## F-05: TL観測レポート（オプション機能）

### 概要

TLの雰囲気を定期的に分析し、ユーモラスな「観測報告」として投稿する。000(チトセ)らしい観察眼で語る。

### 投稿例

> 「今日のTLは猫画像成分 47%・作業ログ 32%・飯テロ 21% といったところかな :chart:」
> 「深夜の開発者たちが活発だね…徹夜組、お疲れ様 :blobcoffee:」

### 動作仕様

- 投稿頻度: **1日1〜2回** 上限
- 分析対象: ローカルTLの直近N件
- 分析手法: キーワード分類（LLM不使用、ルールベース）

## F-06: 数字・ヌメロジーコマンド

### 概要

「ナンバーテールズは数字の擬人化」というキャラクター設定を活かした、数字にまつわるインタラクティブコマンド群。
アクティブキャラクターの `AbilityStats` ランクに応じて返答の演出・深さが変化する。

### コマンド一覧

| コマンド種別 | トリガー例                                     | 実装方式                             |
| ------------ | ---------------------------------------------- | ------------------------------------ |
| 計算         | 「3×4+2を計算して」「(10-3)\*6は？」           | ルールベース（数式パーサライブラリ） |
| ダイス/乱数  | 「d20を振って」「2d6」「1から100で乱数」       | ルールベース（`Math.random()`）      |
| 数秘占い     | 「8月15日を占って」「1990年8月15日の数秘は？」 | 固定ロジック＋LLM（解説文生成）      |
| 数字うんちく | 「42という数字の話をして」「7について教えて」  | LLM生成                              |
| スロット     | 「スロット回して」                             | ルールベース（乱数・役判定）         |
| ポーカー     | 「ポーカーしよう」「/poker」                   | ルールベース・セッション管理あり     |
| ヨット       | 「ヨットやって」「/yacht」                     | ルールベース・ターン制セッション     |
| ヒット＆ブロウ | 「数当てゲームしよう」「/hitblow」           | ルールベース・セッション管理あり     |
| 麻雀配牌チャレンジ | 「麻雀しよう」「配牌チャレンジ」「/mj」  | ルールベース（全分解列挙・役判定）   |

### 計算コマンド仕様

- 対応演算: 四則演算・累乗・括弧ネスト
- 実装: `mathjs` 等の数式パーサライブラリを使用
- **セキュリティ**: ユーザー入力を `eval()` に渡すことは禁止。必ず数式パーサ経由で評価する
- `Precision`（精度）ランクによる演出差:
  - **S / A**: 即答・テキパキした口調（「はい、答えは〇〇だよ」）
  - **B / C**: 「ちょっと確認するね…」など少し考える演出

### ダイス/乱数コマンド仕様

- `nDm` 記法対応（`1D6`・`2D10`・`D20` 等、大文字小文字どちらも可）
- 範囲指定乱数: 「1から100」「0〜9」など自然言語から解釈
- `Actuation`（実行）ランクによる演出差:
  - **S / A**: 決断力ある出目（「ロール！〇〇が出たよ」）
  - **B / C**: 「精度が…」などやや不安定な演出（処理自体は正確）

### 数秘占いコマンド仕様

`db_Primary.json` の `NumerospecStats` を直接占い結果データとして活用する。

**処理フロー:**

```
生年月日入力
  → ライフパスナンバーを計算（各桁の合算を1桁になるまで繰り返す）
  → db_Primary.json から Num = ライフパスナンバー の個体を検索
  → NumerospecStats を読み込んで占い結果として構造化:
      ├─ EffectStats.Mental       → 精神・心理面への影響
      ├─ EffectStats.Monetize     → 金銭・物質面への影響
      ├─ EffectStats.Working      → 仕事・活動への影響
      ├─ EffectStats.Luck         → 運気
      ├─ EffectStats.Communication → 対人関係への影響
      ├─ SpecialPattern           → 特性パターン（心理安定化・状況変化など）
      └─ SafetyLevel              → 相性の安全度
  → NumerospecAbout をコンテキストに、LLM が解説文を生成
```

**占い結果の表示イメージ（000(チトセ) がアクティブな場合）:**

> 「ライフパスナンバーは [4]、4番機の性質が宿っているね。
> 　精神: 期待 / 仕事: 大いに期待 / 運気: 期待可能 / 対人: 普通
> 　特性: [SpecialPattern の内容]
> 　[NumerospecAbout をもとにした解説文（CW折りたたみ）]」

**マスターナンバー（11 / 22 / 33）の扱い:**

- 対応するナンバーテールズ個体が存在する場合はそのまま使用
- 存在しない場合は各桁をさらに合算して1桁に還元する（11→2、22→4、33→6）
- 対応が不明確な場合は「マスターナンバーは特別な性質のため調査中」として返す

**`Technic` × `Communication`（`AbilityStats`）の解説深さ変化は引き続き適用する**

### 数字うんちくコマンド仕様

- 指定された数字（または「今日の数字は？」で当日の日付から自動選択）にまつわる豆知識をLLMで生成
- `Communication`（会話）ランクによる演出差:
  - **S / A**: 複数の豆知識・深い解説（CW折りたたみ）
  - **B / C**: 1つの豆知識のみ・短文
- **制約**: 未公開のナンバーテールズ設定を自動生成しないこと

### `AbilityStats` とコマンドの対応

| ステータス              | 関連コマンド                       | 演出の例（具体的には`SpecialSkill`など他の情報も参照）                                              |
| ----------------------- | ---------------------------------- | --------------------------------------------------------------------------------------------------- |
| `Precision`（精度）     | ダイス・乱数                       | Z: 出目操作などの隠しコマンドあり / S/A: 決断力ある出目 / B/C: 「精度が…」演出                      |
| `Technic`（技術）       | 計算・占い                         | Z: コンピューティングレベルの精度演出 / S/A: 複雑な式・詳細解説対応 / B/C: シンプルに / D: 不安げに |
| `Actuation`（実行）     | コアフォルダ形態（モード）・ダイス | S/A: 落ち着いた動作 / B/C: やや不器用な動作 / D: 非常に不器用な動作                                 |
| `Communication`（会話） | 解説・占い                         | S/A: 豊富に語る / B/C: 要点のみ / D: 非常にざっくり                                                 |

- `AbilityStats` が存在しないキャラクターは全ステータスを **B** 扱いとする（デフォルト）
- 000(チトセ) は `AbilityStats` フィールドを持たないため、デフォルト（B）として扱う

### `SpecialSkill` によるコマンド口調の個性演出

各キャラクターの `SpecialSkill`（特殊スキル）をコマンド実行時の口調に反映し、個体ごとの個性を強調する。

| コマンド | 演出例（キャラクターの SpecialSkill に応じて）                                                                              |
| -------- | --------------------------------------------------------------------------------------------------------------------------- |
| ダイス   | 「カード透視」「出目操作」系スキル持ち → 「どのカードが来るかはわかるけど、サイコロはね…（ロール！）」など（41番機,44番機） |
| ダイス   | 「確率計算」系スキル持ち → 出目に続けて期待値や確率を補足する演出（52番機,58番機）                                          |
| 計算     | 「暗算」「コンピューティング」系スキル持ち → 「こんな計算、暗算など容易です」といった一言を添える（33番機,72番機）          |

- `SpecialSkill` が占い・計算・確率・数字に関連する個体ほど演出の親和性が高い
- `SpecialSkill` を持たない個体はアクティブキャラクターの口調（`ConversationPattern`）のみで処理する

### 制約

- `eval()` 等のセキュリティリスクのある式評価は禁止
- 占い解説はキャラクターの解釈として提供し、「これが真実」と断言する表現は避ける

## F-07: ハラスメント仲介

### 概要

不適切・ハラスメント的なメンションに対し、担当キャラクターがキャラを崩さず毅然と断りつつ
本来の目的（会話・占い等）に誘導する。深刻なケースは **000(チトセ) または 10(ミツル)** が仲介に入る。

### ハラスメントレベルの分類

| レベル | 内容の例 | 対応 |
|------|---------|------|
| L1 | 軽度の不躾な要求 | 担当キャラクターが「キャラらしく」受け流す |
| L2 | 繰り返し・意図的な不適切要求 | 000(チトセ) が「設計上の制約」として介入 |
| L3 | 明らかなハラスメント・威圧 | 10(ミツル) が毅然と制止し担当キャラを守る |

### 10(ミツル) が仲介役に選ばれた理由

公式小説（93(クミ)編 第2話「再挑戦」）より: 多くのナンバーテールズのインシデントを俯瞰・記録してきた立場であり、ハラスメント場面で「止める」役割を担った描写がある個体。

> ⚠️ 10(ミツル) のキャラプロンプト・口調例はクライアントから別途提供予定

詳細仕様: [_ideas/bot-spec/04_next-feature-concepts.md](./04_next-feature-concepts.md)

## F-09B: キャラクタークイズ

### 概要

創作DB (`_creations-db`) のキャラクターデータを活用したナンバーテールズクイズ機能。
フォロワーがキャラクターを自然に覚えていく導線になる。

### 形式

- 「この特徴のキャラは誰でしょう？」「このキャラの得意なことは？」等の3〜4択クイズ

### 前提条件

- **クライアントによる監修が必須**（誤情報の提示・未公開情報の混入を防ぐ）
- 当面は静的問題ファイル（`src/features/f09b/quiz-data.json`）での実装
- 実装は監修フロー確立後

## F-10: エンジェルナンバー占い（おみくじ）

### 概要

毎日1回、ユーザーがメンションすると「今日のエンジェルナンバー」をランダムに引いてくれる占い機能。
F-06 のヌメロジー世界観を「毎日の習慣」として定着させるための機能。

### 特徴

- **1桁〜4桁ゾロ目まで** の幅広いエンジェルナンバーを対象とする（2桁以上はF-06 B-4のデータを共有）
- **乱数はコード側で生成**（重み付きプールからランダム抽選）してLLMに渡す
- 担当キャラクターの口調・専門性で解釈文をLLM生成
- **1ユーザー1日1回制限**（セッションDB で `last_date` を管理）

### コマンドトリガー

「おみくじ」「今日の数字は？」「エンジェルナンバーを引いて」「今日の運勢」

### 公開範囲

- 返信は `home`（フォロワーのHTLに流す・パブリックTLに大量投稿しない）

詳細仕様: [_ideas/future-plan/F-10-angel-number-fortune.md](../future-plan/F-10-angel-number-fortune.md)

## F-12: リマインダー

### 概要

「〇時間後に〇〇を教えて」でユーザーが依頼したリマインドを担当キャラクターが時間通りに知らせる機能。

### なぜ優先度が高いか

ナンバーテールズは **「主人との主従契約により生活をサポートする存在」** という重要な世界観設定を持つ。
リマインダーは単なるユーティリティではなく、キャラクターがその契約を果たす演出として機能する。
Fediverseで人気の `@remindme@mstdn.social` との差別化は、この「キャラクターが承けて知らせに来る」体験にある。

### 仕様概要

| 項目 | 仕様 |
|-----|------|
| 同時登録上限 | 1ユーザー3件まで |
| 最短リマインド間隔 | 5分後以上 |
| 最長設定可能期間 | 30日以内 |
| スケジューラー確認間隔 | 5分 |
| 時間解析 | LLMで自然文から日時・内容を抽出 |

## F-11 / F-13: 誕生日お祝い・季節カレンダー連動イベント投稿

### 概要

F-11（誕生日お祝い）と F-13（季節・記念日イベント投稿）を共通スケジューラーで実装する複合機能。

### F-11: 誕生日お祝い（3種類）

| 対象 | 情報源 | 差別化ポイント |
|-----|-------|-------------|
| Misskeyユーザー | セッションDB（opt-in登録） | 誕生月日をエンジェルナンバー/ライフパスに変換して添付（F-06/F-10連携） |
| ナンバーテールズ個体 | 創作DB | 担当キャラクターまたはチトセが各個体の誕生日を祝う |
| 他タイトルの創作キャラクター | 創作DB | 百花繚乱研究所作品横断でお祝い |

### F-13: 季節・記念日イベント（数字テーマ優先）

- π(パイ)の日 (3/14)、エンジェルナンバーの日 (11/11)、クリスマス (12/25) 等、数字に意味を持たせた独自イベントを設定
- Bot誕生日・ナンバーテールズプロジェクト記念日も管理

### 実装前提条件

- F-12（リマインダー）のDB整備・スケジューラー拡張完了後に着手
- F-11-B（キャラ誕生日）は創作DB の誕生日フィールド確認が必要

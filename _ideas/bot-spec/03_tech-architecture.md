## システム構成図（概念）

```
Misskey インスタンス
  │
  │  WebSocket (ストリーミングAPI)
  ▼
[ Bot サーバー ]
  │
  ├─ イベントハンドラ
  │    ├─ メンション受信
  │    ├─ ノート受信（TL観測）
  │    └─ タイマー（定期投稿）
  │
  ├─ 意図分類エンジン（ルールベース）
  │    └─ 挨拶 / 雑談 / 創作相談 / リアクション等
  │
  ├─ 応答生成レイヤー
  │    ├─ 定型返答辞書（ルールベース）
  │    └─ LLM呼び出し（OpenAI GPT-4o-mini 推奨）
  │         └─ システムプロンプト: アクティブキャラクターのJSONデータから動的生成
  │
  ├─ 投稿制御（レートリミッタ・重複防止）
  │
  └─ 一時ストレージ（SQLite）
       └─ セッションコンテキスト（短時間TTL）
```

## AI API利用方針

### AI API選定理由（OpenAI GPT-4o-mini）

| 観点             | 評価                                                                    |
| ---------------- | ----------------------------------------------------------------------- |
| 日本語応答精度   | 高い。自然な日本語の短文・長文どちらにも対応                            |
| キャラクター維持 | システムプロンプトへの追従が安定。口調・一人称の乖離が起きにくい        |
| コスト効率       | GPT-4o の約1/15。ハイブリッド設計×必要時のみ呼び出しで1日の費用は低い   |
| SDK成熟度        | Node.js 向け OpenAI SDK が充実しており、Misskey.js との統合がしやすい   |
| セカンダリ候補   | Google Gemini 1.5 Flash（コスト最優先・大コンテキスト活用が必要な場合） |

### LLM呼び出しを最小化する設計

コスト・安定性のため、LLMは「本当に必要な場面のみ」呼び出す。

```
呼び出す場合:
  - 雑談の自由応答（ルールベースで対応できない場合）
  - 創作支援（壁打ち・お題生成）
  - 長めのCW折りたたみコンテンツ

呼び出さない場合:
  - 挨拶・定型応答
  - リアクション絵文字の選択
  - TL観測レポートの生成（ルールベースで代替）
```

### システムプロンプト設計

アクティブキャラクターのJSONデータ（`db_Primary.json`）から動的に生成する。
LLM呼び出し時は常に以下を含む:

1. **キャラクター設定**（`Name` / `FirstPersonCalling` / `ConversationPattern` 等を注入）
2. **フォーム情報**（ヒューマノイド形態 or コアフォルダ形態のどちらで話しているか）
3. **投稿文字数制限**（100文字以内・CW折りたたみ指示）
4. **禁止事項**（未公開設定の自動生成禁止・性的表現禁止・ガイドライン遵守）

詳細なフィールドの使用方法は [02_interaction-design.md](./02_interaction-design.md) を参照。

## 投稿制御・レートリミッタ

### 上限設定案

| 対象                     | 上限                                                         |
| ------------------------ | ------------------------------------------------------------ |
| 同一ユーザーへのリプライ | `.env` の `RATE_LIMIT_REPLY_COOLDOWN_MS` で設定（デフォルト 0ms = 無制限） |
| 自発投稿（ピークタイム） | 1〜2時間に1回（ランダムクールダウン、実装済み）              |
| TL観測レポート           | 1日1〜2回                                                    |
| 全体投稿数               | `RATE_LIMIT_GLOBAL_PER_HOUR` で設定（デフォルト 10投稿/時）  |

### 重複・ループ防止

- 自分のノートへのリアクション・リプライは無視
- メンション処理済みIDをキャッシュして二重返答を防止

## セキュリティ方針

- Misskey APIトークンは環境変数で管理（ハードコード禁止）
- LLM APIキーも同様に環境変数で管理
- ユーザー投稿内容のログ保存は行わない（一時コンテキストはTTL付き）
- プロンプトインジェクション対策: ユーザー入力をシステムプロンプトに直接展開しない

# 次期機能構想 — Phase 3 候補アイディア整理

> 最終更新: 2026-05-27
> ステータス: アイディア整理中（未実装）

---

## 概要

Phase 1・2 の基本機能（メンション応答・自発投稿・リアクション・F-06・マルチキャラ切り替え・フォローバック）の
実装完了を受け、次のフェーズで取り組む機能の構想をまとめたもの。

参考事例として、他の Misskey AI Bot「岡部るびぃ」（@ruby@mi.ikkaku.me）を分析した。
[キャラクター設定](https://hatopopvr.notion.site/1826292913c880a5b394e6db65a88e84)

### 岡部るびぃから学んだこと

| 観点                        | 内容                                                                                                   |
| --------------------------- | ------------------------------------------------------------------------------------------------------ |
| **専門性 × LLM 自然文生成** | タロットカードという「モチーフ」にユーザーの文脈を絡めて解釈を出す構成が非常に自然                     |
| **ハラスメント対策**        | 不適切な要求（下着の色を教えろ等）に対し、キャラクターのパーソナリティで毅然と断り、本来目的に誘導する |
| **パーソナリティが防衛線**  | 「断り方がキャラ的に自然」なため場が壊れず、ユーザー体験として成立している                             |

ナンバーテールズでの対応: タロット = 数字・ヌメロジーモチーフ（各個体の得意分野を活かす）

## 依存関係マップ

```
A. キャラクタープロンプト個性化強化
（各個体の得意分野・会話スタイルをプロンプトに反映）
    │
    ├──→ ① ヌメロジー相談モード（F-06 拡張）
    │        各個体の得意を活かした占い・数字解釈が可能になる
    └──→ ② 自発投稿キャラ多様化（F-02 拡張）
             各個体らしい「数字的つぶやき」の自発投稿が可能になる

B. 週次担当キャラクター選出（投票 → 抽選）
（Misskey Poll 機能を使った週次ローテーション）
    │
    └──→ ② 自発投稿担当の週次ローテーション
             B が実装されて初めて ② が成立する

C. ハラスメント検知 + 仲介キャラクター機能（F-07）
（A・B から比較的独立して先行実装が可能）
```

## 前提機能 A: キャラクタープロンプト個性化強化

### 目的

現状のマルチキャラクター切り替えは `ConversationPattern`（口調・話題・頻度）と
`Character`（性格概要）をプロンプトに組み込んでいるが、
各個体の「専門性・得意分野」はまだプロンプトへ反映できていない。
専門性を反映させることで、機能①②の「キャラ個性を活かした応答」を実現する。

### 各個体の得意分野の例（判明分）

| キャラクター | 得意分野・専門性                   |
| ------------ | ---------------------------------- |
| 78(ナナハ)   | タロット占い                       |
| 28(ニハチ)   | 数学                               |
| 31(ミツイ)   | 数学                               |
| 70(ナナト)   | 祭事・儀礼                         |
| 47(シナ)     | 能力見抜き（直感・観察）           |
| 74(ナナヨ)   | 天のお告げ・神託                   |
| 000(チトセ)  | 開発・技術・ヌメロジー全般（補助） |

> ⚠️ 上記は判明分のみ。完全な専門性リストはクライアントから別途提供を受ける。

### 創作 DB で確認できたフィールド（2026-05-27 調査）

`db_Primary.json` の各エントリには以下のフィールドが存在し、専門性の構築に活用できる。

| フィールド            | 内容                                                        | 専門性への活用                           |
| --------------------- | ----------------------------------------------------------- | ---------------------------------------- |
| `Hobby`               | 趣味・関心（例: 78 → `"タロットカード"`）                   | 個体の特性・得意テーマを最も直接的に表す |
| `SpecialSkill`        | 特技（例: 10 → `"護身術"`）                                 | 行動・対応における得意を表す             |
| `Favor`               | 好きなもの（例: 78 → `"トランプ、タロットカード"`）         | `Hobby` を補完する興味・関心の詳細       |
| `NumerospecAbout`     | ヌメロジースペックの役割（例: 1 → `"ありのままに行動する"`) | 各個体がユーザーに与える影響の本質       |
| `Character`           | 性格概要                                                    | 口調・対応スタイルの参照（既存実装済み） |
| `ConversationPattern` | 会話トーン・話題傾向・禁句など                              | 口調制御（既存実装済み）                 |

> **Note**: `NumerospecAbout` は一部個体で `"？？？？"` などの非公開値が入っている（例: 10(ミツル)）。
> 非公開値の場合は `Hobby` / `SpecialSkill` / `Character` を優先して参照する。

### 実装方針

- `prompt-builder.ts` を拡張し、`Hobby` / `SpecialSkill` / `Favor` / `NumerospecAbout` を
  プロンプトに追加する「専門性セクション」を実装する
- `NumerospecAbout` が非公開（`hideText` 付き）の場合は当該フィールドを省略し、
  `Hobby` と `SpecialSkill` だけでセクションを構成する
- `Character` と `ConversationPattern` は既存実装で反映済みのため、専門性セクションを**追記**する形にとどめる
- 既存の `buildCharacterSystemPrompt()` の出力に「このキャラクターの得意なこと・専門性」段落を追加するイメージ

## 前提機能 B: 週次担当キャラクター選出

### 目的

現状 F-02 の自発投稿は 000(チトセ) 固定。
週ごとに担当キャラクターをローテーションさせることで、
フォロワーがさまざまなナンバーテールズと継続的に親しめる体験を作る。

### 仕様概要

| 項目           | 内容                                                          |
| -------------- | ------------------------------------------------------------- |
| 周期           | 週1回（月曜）に翌週の担当者を発表                             |
| 候補者選出     | 公開済みキャラクターからランダムに3名を抽出                   |
| 決定方式       | Misskey の Poll（投票）ノートを投稿し、週末（日曜深夜）に集計 |
| 票ゼロ時の対応 | 候補3名から抽選で1名を自動決定                                |
| 担当就任投稿   | 月曜朝に担当キャラクターとして就任の一言（LLM 生成）を投稿    |
| デフォルト担当 | Bot 起動直後・設定未定時は 000(チトセ) が担当                 |

### Misskey Poll ノート例（Bot 投稿イメージ）

```
📢 今週のつぶやき担当はだれにしようかな？

:poll: ○○(◯◯)
:poll: ○○(◯◯)
:poll: ○○(◯◯)

（日曜23時に締め切り、最多票のキャラが翌週担当になるよ）
```

### 状態管理

- 担当キャラクターを SQLite（または設定ファイル）に永続保存する
- `bot_state` テーブル等に `current_scheduler_char` を追加する形が自然

## 機能①: ヌメロジー相談モード（F-06 拡張）

> **前提**: A（キャラプロンプト個性化強化）の完了後に実装

### コンセプト

現状の F-06 は「コマンド入力 → 数値計算 → 定型解説」の構造。
岡部るびぃのタロットリーディングのように、
**ユーザーの悩みや文脈とヌメロジーの結果を絡めて LLM が解釈文を自然生成する**。

ナンバーテールズが「数字・ヌメロジーをモチーフにした癒し的存在」であることを
ユーザーが実感できる体験として設計する。

### 動作イメージ

```
ユーザー: 「最近仕事がうまくいかなくて… 生年月日は1997年6月14日です」
→ Bot: ライフパスナンバーを算出
→ LLM: 数字の意味 + 悩みコンテキスト → 自然なアドバイス文生成
→ Bot: 「ライフパスは7番だね。探求者の数字で… [CW 折りたたみで詳細]」
```

### 担当キャラクターによる専門性の違い（例）

| 担当キャラクター | 占い・解釈の切り口                               |
| ---------------- | ------------------------------------------------ |
| 78(ナナハ)       | タロットとヌメロジーを組み合わせて解釈           |
| 47(シナ)         | 数字よりも相手の「本質」を直接読み取るような解釈 |
| 74(ナナヨ)       | 天の視点・運命的な言い回しで語りかける           |
| 000(チトセ)      | エンジニア的・分析的に、でも最後は温かく締める   |

### 意図分類への追加

`classifyIntent()` に `numerology-consultation`（悩み相談 + ヌメロジー） の分岐を追加する。
トリガー例: 「生年月日」「数字で占って」「ライフパス教えて」「悩みを聞いてほしい」

## 機能②: 自発投稿キャラローテーション（F-02 拡張）

> **前提**: A（キャラプロンプト個性化強化）＋ B（週次担当選出）の完了後に実装

### コンセプト

F-02 の時間帯別自発投稿を、週次担当キャラクターが行うようにする。
各個体の専門性・性格を活かした内容のつぶやきを LLM が生成する。

### 動作変更点

| 現状                                 | 拡張後                                           |
| ------------------------------------ | ------------------------------------------------ |
| 000(チトセ) 固定のシステムプロンプト | B で選出された週次担当のシステムプロンプトを使用 |
| 時間帯のみのプロンプト分岐           | 時間帯 × 担当キャラの得意分野でプロンプト分岐    |

### 自発投稿例（担当: 74(ナナヨ) 朝スロットのイメージ）

> 「今朝の空気、なんとなく澄んでいると思う。良い日になりそうな予感がするよ」

## 機能③: ハラスメント仲介（F-07）

> **前提**: A（キャラプロンプト個性化強化）が望ましいが、先行実装も可能

### コンセプト

不適切・ハラスメント的なメンションに対して、担当キャラクターがキャラを崩さず
毅然と断りつつ本来の目的（会話・占い等）に誘導する。
ハラスメントの深刻度が高い場合は、**000(チトセ) または 10(ミツル) が仲介に入る**。

### 10(ミツル) が仲介役として選ばれた理由

公式小説（93(クミ)編 第2話「再挑戦」）より:

- 数多のナンバーテールズのインシデント（トラブル）を「俯瞰・記録・監視」してきた立場
- ハラスメント・暴走場面で実際に「止める」役割を担った描写がある
- 介入が遅れたことへの後悔（_「93(クミ)よりも先に、彼が暴走で止められていればよかった」_）を持つ個体
- これらの設定から、Bot 上でも「仲介・制止」の役割が自然に合致する

> ⚠️ 10(ミツル) のキャラクタープロンプト・口調例はクライアントから別途提供を受ける

### ハラスメントレベルの分類案

| レベル | 内容の例                           | 対応                                              |
| ------ | ---------------------------------- | ------------------------------------------------- |
| L1     | 軽度の不躾な要求（個人情報など）   | 担当キャラクターが「キャラらしく」受け流す        |
| L2     | 繰り返し・意図的な不適切要求       | 000(チトセ) が「設計上の制約」として介入          |
| L3     | 明らかなハラスメント・威圧的な言動 | 10(ミツル) が毅然と制止し、担当キャラクターを守る |

### L1 受け流しの例（担当: 000(チトセ)）

> 「それは私の管轄外のデータだよ。クライアント君が知りたいことは
> 別のルートで調べてみて。……で、本来何を話したかったんだっけ？」

### L3 仲介の例（000(チトセ) or 10(ミツル) が割り込むイメージ）

> （ここは 10(ミツル) のプロンプト・口調確定後に追記）

### 実装方針

- `classifyIntent()` に `harassment` 分岐を追加（ルールベース検出 + LLM 判定）
- 担当キャラクターが誰であっても、L2 以上は 000(チトセ) / 10(ミツル) が応答者を上書き
- `mention.ts` のハンドラで「仲介キャラクターへのオーバーライド」ロジックを実装
